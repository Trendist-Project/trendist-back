# Trendist 1부. 기획

> 문서 목록과 변경 이력은 [docs/README.md](README.md). 절 번호(1~17)는 네 문서에 걸쳐 이어지고, 코드 주석의 `(4.8)` 같은 번호가 이 번호다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 서비스 | Trendist, 도메인 trendist.kr(예정) |
| 장르 | 실시간 멀티플레이 .io 아레나. 원형 아이콘끼리 부딪히면 큰 쪽이 작은 쪽을 밀어낸다 |
| 플랫폼 | 브라우저(데스크톱 우선, 모바일 대응), 설치 없음 |
| 운영 형태 | 라운드 없이 24시간 계속 유지되는 아레나 |
| 지역 | 나라별로 방·트렌드를 나눈다. 지금은 한국(KR)과 글로벌(GLOBAL, 영어권 통합)을 연다. 이후 일본·인도. 중국은 열지 않는다 |
| 언어 | 한국어·영어(지금 지원) → 일본어·중국어(간체)·힌디어 |
| 핵심 재미 | 뜨는 키워드를 찾아 `+`하면 커지고, 커지면 부딪힐 때 이긴다 |
| 데이터 | 한국은 구글 트렌드 실시간 인기(RSS). 해외 지역의 외부 소스는 정하지 않았다(16.1). 외부 데이터는 "지금 뜨는 키워드인가"를 확인하는 데 쓰고, 점수의 크기는 가진 사람 수와 소스별 반영값으로 정한다 |

기획 배경
- 유행 주기가 급격히 짧아졌다. 탕후루 54일(2023), 두바이 초콜릿 13일(2024), 두쫀쿠 17일(2025 말)로 5년 사이 약 10분의 1이다(위키트리, 2026-07-25).
- 짧은 유행일수록 "누가 먼저 알았나"가 가치가 된다. 이 게임은 유행을 찾아 `+`한 만큼을 아이콘 크기로 보여 준다.
- 매일 바뀌는 키워드 데이터가 콘텐츠라서 특정 유행이 끝나도 게임이 낡지 않는다.

핵심 규칙 요약 (자세한 내용은 괄호의 절)
- 보관함: `+`한 키워드는 24시간 뒤 사라지고, 같은 키워드는 한 번만 `+`한다(4.5).
- 키워드 상태는 💤비활성 / 🔥활성 / ⛔금지 세 가지다. 외부 데이터에서 확인되거나 가진 사람이 3명 이상이면 🔥가 된다(4.7).
- 키워드 점수: `trend_value = 소스 가중치(지금은 모든 소스 1) × (3 + 47 × g(가진 비율))`, 키워드 점수는 `trend_value` 그대로다(트렌드 값 = 내 유행도에 더해지는 점수). 가진 비율은 그 나라 활동 인원(키워드를 가진 플레이어) 중 이 키워드를 가진 사람의 비율이고, g는 50%에서 1이 되는 로그 곡선이다(4.8).
- 현재 유행도(플레이어 점수) = `min(EXP, 100)` + 내 🔥 키워드 점수의 합. 키워드의 값이 바뀌면 보유자의 점수와 원 크기가 실시간으로 바뀐다(4.8, 9.2).
- 원 크기: 반지름 16~600px(최대 지름은 기준 맵 한 변의 2.5%). 커질수록 화면이 줌아웃된다(4.2, 4.8).
- EXP는 `+` 횟수로만 쌓인다(1회 = 1 EXP). 레벨은 1~100이고 레벨별 필요 EXP는 DB(`levels`)에서 관리한다(4.9).
- 충돌: 현재 유행도가 낮은 쪽이 키워드 하나를 잃는다(4.3). 랭킹은 현재 유행도 순서로만 정한다(4.14).
- 칭호는 누적 `+` 횟수, 레벨, 보유 키워드 수, 현재 유행도, 댓글 점수로 만든다(4.10).
- 급상승 목록과 키워드 순위는 공개하지 않는다(3.3).

## 2. 플레이 흐름

```
접속 → 메인 화면 → [시작] 또는 [Google로 시작] → 닉네임 → 아레나 입장
→ 검색창에 키워드 입력 → 트렌드 값 확인 → [+] → 보관함에 추가, 아이콘 커짐
→ 다른 플레이어와 충돌(큰 쪽이 밀어냄) → 24시간 뒤 `+`가 사라지면 새 유행을 찾아 다시 검색
(검색 결과가 없는 새 단어도 바로 `+`할 수 있다.
 외부 데이터에서 사라지고 가진 사람도 3명 미만인 키워드는 💤비활성으로 잠들고, 다시 뜨거나 3명이 모이면 깨어난다)
```

## 3. 화면

### 3.1 메인 화면

```
┌──────────────────────────────────────────────────────────────┐
│  (배경: 원들이 떠다니며 커졌다 작아지는 아레나 애니메이션)            │
│                         Trendist                             │
│                  트랜드를 아는 자, 커진다.                        │
│     남들보다 먼저 뜨는 키워드를 찾아 +하고, 내 원을 키워 보세요.        │
│        🔍 키워드 찾기   →   ➕ 먼저 +하기   →   ⭕ 원이 커진다          │
│                    ┌──────────────────────┐                  │
│                    │        시작          │                  │
│                    └──────────────────────┘                  │
│                    ┌──────────────────────┐                  │
│                    │ G  Google로 시작       │                  │
│                    └──────────────────────┘                  │
│          로그인하면 다른 기기에서도 기록이 이어져요                   │
│   지금 1,284명이 플레이 중   [공지] [가이드] [이용약관] [개인정보]    │
└──────────────────────────────────────────────────────────────┘
```

- 서버(나라) 선택: 메인 화면 카드 맨 아래에 '서버' 라벨이 붙은 작은 목록으로 둔다. 기본값이 알아서 정해지므로 눈에 덜 띄게 하고, 서버(게임 방)와 언어가 함께 바뀐다는 설명을 붙인다(나라 = UI 언어, KR=한국어, GLOBAL=영어, 4.18). 처음 열면 브라우저 언어가 한국어면 KR, 아니면 GLOBAL이 골라져 있고, 고른 값은 브라우저(localStorage `trendist.country`)에 남는다. 나라를 바꾸면 페이지를 새로 불러온다.
- 접속하거나 새로고침하면 누구나 메인 화면부터 시작한다. 로그인 사용자는 갱신 토큰이 유효하면(마지막 접속 후 1일 안) [시작]을 눌렀을 때 저장된 닉네임·나라로 바로 게임 화면에 들어간다.
- [시작]은 로그인한 계정(갱신 토큰)이 있으면 그 계정으로, 재방문 게스트면 그 게스트로 이어 가고, 처음이면 로그인 없이 게스트로 시작한다(이때 게스트 행과 방문자 ID가 만들어진다). [Google로 시작]는 로그인 후 바로 게임 화면으로 들어간다(그 나라에서 처음이면 닉네임부터 정한다. 탈퇴한 계정이면 복구 여부를 먼저 묻는다, 4.1).
- 게스트 첫 방문은 닉네임 입력과 나라 확인을 한 화면에서 하고 입장한다. 게스트 재방문은 메인 화면에서 [시작]을 누르면 쿠키의 방문자 ID로 같은 계정을 이어 받아 저장된 닉네임·나라로 바로 입장하고(새 게스트 행을 만들지 않는다), [설정] 링크로 바꿀 수 있다.
- 이미 구글 계정으로 로그인한 상태(갱신 토큰이 유효)면 [Google로 시작]와 "또는" 구분선, 로그인 안내 문구를 숨기고 [시작]만 보여 준다. 화면을 열 때 세션만 이어 보고(새 게스트 행은 만들지 않는다) 게스트가 아닌 계정인지로 정한다. 확인하는 동안에는 구글 버튼을 띄우지 않는다.
- [시작]과 [Google로 시작]는 같은 크기(폭 전체, 높이 52px, 모서리 12px)이고 사이에 "또는" 구분선을 둔다. 구글 버튼은 구글 브랜드 모양(흰 바탕, G 로고)이다. 누르면 구글 계정 선택 페이지로 가서 매번 계정을 고른다(다른 계정 추가 가능).
- [시작] 위에 네 줄 안내를 둔다: "🕹 모바일은 조이스틱, PC는 클릭·방향키로 이동" / "⭕ 큰 원이 작은 원을 튕겨내요" / "💥 지면 키워드 1개를 잃고, 이기면 그 키워드를 뺏음" / "🛡 키워드 잃으면 3초 무적 · 세이프존 안은 안전".
- 제목(Trendist) 위에 로고(T와 오르는 화살표)를 둔다. 같은 로고를 브라우저 탭 아이콘(게임·관리자)과 iOS 홈 화면 아이콘으로 쓴다. 원본과 만든 파일은 프론트 저장소 `branding/`과 `public/`에 있다.
- 배경 애니메이션은 미리 만든 연출이고 실제 키워드를 쓰지 않는다. 원 14개가 저마다 다른 경로·속도(4~11초 한 바퀴)로 크게 움직이며 커졌다 작아진다. `prefers-reduced-motion`이면 정지 이미지로 바꾼다.
- 새 공지 팝업(4.16)은 게스트는 이 화면에서, 로그인 사용자는 게임 화면에 처음 들어올 때 뜬다. 방이 가득 차면 "지금은 접속자가 가득 찼어요"를 보여 준다.
- 모바일은 세로로 쌓고, 키보드로 [시작] → [Google로 시작] 순서로 이동할 수 있게 한다.

### 3.2 게임 화면

```
┌──────────────────────────────────────────────┬──────────────────────────┐
│ 현재 접속 42명   [공지] [가이드] [미니맵 M] [🏆 L] │ [검색] [보관함]          │
│                                              │ ┌──────────────────────┐ │
│          ●민수(큰 원)                         │ │ 양쯔깐루▏              │ │
│                      ●유나                    │ └──────────────────────┘ │
│    ●나(조작 중)                  ●지훈          │ 양쯔깐루  🔥활성          │
│                                              │ 트렌드 67 · 👥 1,204명    │
│                                              │              [ + ]        │
│ [채팅 로그]                                    │ ──────────────────────── │
│ 유나: 양쯔깐루 지금 +하면 이득임                  │ 내 유행도 148 · 🐻 5레벨   │
│ [입력창____________________] [Google 로그인]   │                          │
└──────────────────────────────────────────────┴──────────────────────────┘
```

- 모바일(화면 너비 760px 이하)은 아레나가 화면 대부분을 쓴다.
  - 검색·보관함은 하단 시트다. 처음에는 탭 줄([🔍 검색] [📦 보관함] [▴])만 보이고, 탭을 누르면 화면 절반쯤(최대 460px)으로 펼쳐지며, 펼친 탭이나 [▾]를 누르면 접힌다. 채팅의 `#키워드`를 누르면 검색 탭이 펼쳐진다.
  - 오른쪽 위에는 [🔍 정보 보기]와 [☰ 메뉴] 두 버튼만 둔다(40px). 메뉴에는 내 정보·공지사항·가이드·FAQ, 미니맵·리더보드·채팅·조작 설명(켜짐/꺼짐 표시), 이동 방식(조이스틱/터치 이동), 로그인/로그아웃을 이름과 함께 모은다. 아레나를 누르면 메뉴가 닫힌다. 왼쪽 위 접속 인원은 "👥 3 · 🤖 7"처럼 짧게 보여 준다. 버튼이 많아 접속 인원 표시와 겹치던 것을 막는다. 아래쪽 내 정보 줄은 레벨 아이콘·Lv.·닉네임·유행도만 한 줄로 보인다.
  - 처음 들어왔을 때(저장된 선택이 없을 때) 리더보드와 조작 설명 카드는 접혀 있고, 채팅은 접힌 상태(마지막 한 줄 + 입력창)다.
  - 공지·가이드·키워드 상세·신고 창은 아래에서 올라오는 전체 폭 시트로 열린다. 입력창 글자는 16px(iOS가 입력할 때 화면을 확대하지 않게).
- 아이콘이 커지면 화면이 조금씩 줌아웃된다(4.2).
- 내 닉네임이나 아이콘을 누르면 내 정보 창이 열린다. 지금은 [👤 내 정보] 버튼과 아래쪽 HUD의 내 닉네임으로 연다. 레벨·EXP·내 유행도·보유 키워드 수·누적 `+` 횟수를 보여 주고 닉네임을 바꿀 수 있다(4.1). 창 안의 [🏅 칭호]로 칭호함(4.10), [🎨 꾸미기]로 꾸미기 프로필(4.9, 이동 효과 4.23 포함), [📸 자랑하기 카드]로 공유 카드·주소(4.24)를 열고, 기록에는 빼앗기·봇 사냥·활동한 날도 보이며, 계정 칸에 로그아웃과 [회원 탈퇴](4.1)를 둔다.
- 아레나 오른쪽 위에 [내 정보] [공지사항] [가이드·FAQ] [미니맵(M)] [리더보드(L)] [채팅(C)] [?] 버튼을 둔다. 공지사항(4.16)과 가이드·FAQ(4.17)는 게임 위에 창으로 열리고 게임은 멈추지 않는다.
- 아레나 오른쪽 아래에 이모트 버튼 [😀](4.26)을 미니맵 바로 위에 두고(미니맵을 끄면 오른쪽 아래 모서리로 내려감), 내 연속 빼앗기 콤보(4.25)는 오른쪽 도구 줄의 리더보드 아래에 보여 준다(위쪽 가운데는 ? 구슬 결과와 겹친다).
- 리더보드(4.14)는 버튼 줄 바로 아래, 아레나 오른쪽 위 모서리에 겹쳐 보여 준다. 미니맵처럼 [리더보드] 버튼이나 L 키로 켜고 끄고, 켜짐 여부를 그 브라우저에 기억한다(처음에는 켜짐).
- [?]는 조작 설명 카드(클릭·탭 이동, 방향키·WASD, 검색 → `+`, M 미니맵, L 리더보드)를 펼치고 접는다. 카드는 오른쪽 아래 이모트 버튼·미니맵 위까지만 내려오고, 화면이 낮으면 설명 목록만 카드 안에서 스크롤한다([가이드 더 보기]·[접기]는 항상 보인다). 처음 들어오면 펼쳐져 있고, 접으면 그 브라우저에 기억해서 다음부터는 접힌 채로 시작한다. 카드에서 가이드로 바로 갈 수 있다.

### 3.3 급상승 키워드 비노출
지금 뜨는 키워드를 보여 주면 모두가 같은 키워드를 따라 `+`해서 안목을 겨루는 의미가 사라진다. 그래서 다음은 두지 않는다.
- 실시간 급상승 목록, 키워드 랭킹, 검색 자동완성·추천 검색어, 키워드 이름을 단 NPC 봇, 메인 화면 배경의 실제 키워드(관리자 화면의 트렌드 키워드 목록, 13.6은 `ROLE_ADMIN`만 본다)

사용자가 직접 찾거나 사람끼리 공유한 정보는 보여 준다: 직접 검색한 키워드의 카드(활동 그래프 포함)와 트렌드 값·점수·인원, 다른 플레이어 팝업의 상위 3개 키워드(4.11), 채팅의 `#키워드`(4.13). 트렌드 상자(4.19)는 상자를 직접 연 사람에게만 키워드 하나를 잠깐 보여 주는 예외다. ? 구슬(4.20)과 봇을 이긴 보상(4.21)도 그 사람에게만 무작위 🔥 키워드 하나를 주는 같은 종류의 예외다.

## 4. 게임 규칙

### 4.1 입장과 계정

방문자 ID와 로그인
- 사용자 행은 [시작]이나 구글 로그인을 누를 때 만든다. 게스트는 이때 서버가 방문자 ID(`yyyyMMddHHmmss-UUID`, UTC)를 발급하고 쿠키에 담는다. 메인 화면만 보고 떠난 방문자는 방문자 ID도 사용자 행도 남기지 않는다. 게스트와 로그인 사용자가 같은 사용자 행 체계를 쓴다.
- 쿠키는 1년이고 재방문해도 연장하지 않는다. 쿠키를 지우거나 다른 브라우저로 와서 다시 [시작]하면 새 ID와 새 게스트 행을 받는다.
- 방문자 ID는 인증 수단이므로 다른 사용자에게 보내지 않는다. 화면에는 닉네임만 보여 준다. 다른 플레이어는 방 안에서만 쓰는 세션 엔티티 번호로 가리키고, 사용자 내부 번호(`users.id`)도 다른 사용자에게 보내지 않는다.
- 구글 로그인은 선택이다. 로그인하면 현재 기록이 계정에 연결되어 다른 기기에서도 이어진다. 이미 다른 기록이 연결된 계정이면 계정 쪽을 우선하고 게스트 기록은 합치지 않는다. 구글 이름·이메일·사진은 쓰지 않는다.
- 구현: 메인 화면의 구글 버튼, 게임 중 게스트에게만 보이는 [🔑 로그인] 버튼(도구 줄), 내 정보 창의 [Google로 로그인]·[로그아웃]. [🔑 로그인]과 [Google로 로그인]은 설명 창 없이 누르면 바로 구글 계정 선택 페이지로 가고, 고른 계정으로 로그인한 뒤 게임으로 다시 들어온다. 브라우저에 로그인된 계정이 자동으로 쓰이지 않고 매번 계정을 고른다. 처음 쓰는 구글 계정으로 로그인하면 지금 게스트 행에 OAuth 값(`oauth_type`=GOOGLE, `oauth_id`=구글 sub의 SHA-256)만 채워 닉네임·레벨·보관함·점수가 그대로 이어지고, 게스트가 없으면 OAuth 값만 가진 새 계정을 만든다. 이미 연결된 구글 계정이면 그 계정으로 들어간다. 로그인한 사람은 도구 줄에 [🔑 로그인] 대신 [🚪 로그아웃]이 보인다. 로그아웃하면 갱신 토큰과 이미 발급한 JWT가 바로 무효가 되고 메인 화면으로 가며, 다시 [시작]하면 새 게스트로 시작한다.
- 로그인해야 하는 기능은 이미지 업로드, 픽셀 그림, 댓글 작성, 이동 효과(4.23), 테두리 효과(4.9)다(그림·효과는 꾸미기라 11레벨부터). 채팅, 새 키워드 `+`, 댓글 투표는 게스트도 할 수 있다. 구글 로그인을 만들기 전까지는 댓글 작성도 게스트에게 열어 둔다(4.12).
- 서버의 기록은 기간 제한 없이 보관한다.

닉네임
- 1~10자(NFC 정규화 후 화면에 보이는 글자 단위). 중복을 허용하고 태그를 붙이지 않는다. 내부에서는 항상 사용자 ID로 구분한다.
- 허용: 영문·숫자·공백·`_` `-` `.`, 그리고 한 가지 문자권(한글 / 일본어 가나·한자 / 한자 / 데바나가리). 문자권을 섞을 수 없다(`민수abc` 가능, `민수たろう` 불가). 전각 영숫자는 반각으로 바꾸고, 앞뒤 공백은 지우고 연속 공백은 하나로 줄인다.
- 금지

| 문자 | 이유 |
|---|---|
| `#` `@` | 채팅의 `#키워드`, 멘션과 혼동 |
| `<` `>` `&` `"` `'` `` ` `` `/` `\` | XSS, 경로·이스케이프 문제 |
| `: ; , { } [ ] ( ) = + * % $ ! ? ~ ^ \|`, 첫 글자 `-` | 링크 파싱, 로그·CSV 인젝션 |
| 제어·보이지 않는·방향 제어 문자 | 화면 깨짐, 같은 모양 닉네임으로 사칭 |
| 결합 문자 남용, 한글 자모 단독, 이모지, 허용 밖 문자권 | 렌더링 번짐, 비슷한 글자로 사칭 |

- 거부할 때 문제 글자를 알려 준다("닉네임에 쓸 수 없는 문자가 있어요: #"). 서버 검사 결과만 믿고, 화면에는 항상 텍스트로만 그린다.
- 예약어 제한은 없다. 진짜 관리자는 닉네임 옆 관리자 배지로 구분한다.
- 변경은 마지막 변경 후 1시간이 지나야 할 수 있다(설정값 `nickname_change_minutes`, 기본 60). 내 정보 창에서 바꾸고, 기다려야 하면 다시 바꿀 수 있는 시각을 보여 준다. 지금과 같은 닉네임으로는 바꿀 수 없다. 바꾸면 접속 중인 방의 이름표도 바로 바뀐다. 처음 정하는 것은 변경으로 세지 않는다. 닉네임은 나라마다 따로 정하고 변경 간격도 나라별로 센다. 새 나라에 처음 들어가면 마지막으로 쓴 닉네임을 미리 채워 보여 주고, 바꿀 수 있다.
- 금지 닉네임: 관리자가 등록한 단어가 닉네임에 들어 있으면 막는다(대소문자·공백·전각 무시). 욕설 목록도 여기서 관리한다. 이미 쓰던 닉네임이 금지되면 그 나라에 다음 입장할 때 바꿔야 하고(이때는 1시간 제한 없음), 접속 중이면 임시 이름 `플레이어`로 바뀐다.

탈퇴와 복구
- 탈퇴하면 DB의 값은 바꾸지 않고 `users.user_state_id`를 탈퇴 상태로 바꾸고 `users.deleted_at`에 시각만 기록한다. 닉네임, 꾸미기, 칭호, 댓글, 보관함 등 저장된 값은 그대로 두고, 갱신 토큰은 모두 폐기한다.
- 화면에 보여 줄 때만 덮어쓴다: 닉네임은 `탈퇴한 사용자`, 아이콘은 기본 아이콘, 칭호는 숨김, 댓글 본문은 "탈퇴한 사용자의 댓글이에요".
- 랭킹·방·정보 팝업에서 빠지고, 남은 보관함은 점수 산정에서 제외한다(24시간 뒤 평소대로 삭제).
- 복구: 탈퇴한 계정과 같은 구글 계정(같은 `oauth_id`)으로 다시 로그인하면 "탈퇴한 계정이에요. 복구할까요?"를 보여 주고, [복구]를 눌렀을 때만 복구한다. 복구하면 상태를 정상으로 되돌리고 `deleted_at`을 비우며 로그인된다. 닉네임, 레벨, EXP, 칭호, 꾸미기, 댓글은 탈퇴 전 그대로 돌아오고, 탈퇴 중에 만료된 `+`는 평소대로 삭제되어 있다. [취소]하면 아무것도 바꾸지 않고 로그인되지 않으며, 게스트로 쓰던 중이면 그대로 게스트로 남는다.
- 구현: 내 정보 창 계정 칸의 [회원 탈퇴](어두운 바탕에서도 보이는 빨간 테두리·옅은 빨간 바탕 버튼)를 누르면 확인 창이 뜬다. "탈퇴 합니다."를 직접 입력해야 [탈퇴]가 눌린다(붙여넣기·끌어 놓기는 막고, 안내 문구도 복사되지 않게 한다). 서버도 같은 문구인지 확인한다(`POST /api/auth/withdraw`). 탈퇴하면 바로 메인 화면으로 간다. 구글로 로그인한 계정만 탈퇴할 수 있다(게스트 기록은 복구할 방법이 없으므로 탈퇴 대상이 아니다).
- 구현: 탈퇴한 구글 계정으로 다시 로그인하면 "탈퇴한 계정이에요" 창에 복구하면 닉네임·레벨·칭호·꾸미기·댓글이 그대로 돌아온다는 안내와 [계정 복구]·[취소]를 보여 준다. [계정 복구]를 누르면 같은 구글 ID 토큰으로 복구 요청을 보내고 바로 로그인해 게임으로 들어간다.
- 방문자 ID(게스트)로는 복구되지 않는다. 탈퇴한 상태에서는 갱신 토큰도 방문자 ID도 세션을 만들지 못하고, 게스트가 같은 브라우저로 다시 오면 새 방문자 ID를 받는다.

### 4.2 아레나와 이동
- 아이콘은 원으로 고정이다. 닉네임은 원 바로 아래, 활성 칭호는 그 아래 작은 글씨로 항상 보인다.
- 원 안의 성장 캐릭터(거북이)는 가는 쪽을 바라본다. 움직이는 방향으로 부드럽게 돌아가고(초당 12배 비율로 따라감, 가까운 쪽으로 돈다), 멈추면 마지막 방향 그대로다. 느린 움직임(초당 25px 미만)과 튕겨 날아가는 것은 방향에 넣지 않는다. 내 원은 예측 속도, 다른 원은 화면에서 움직인 만큼으로 정한다(서버는 방향을 보내지 않는다). 닉네임·칭호 글씨는 돌지 않는다.
- 조작
  - 빈 바닥 클릭(모바일 탭): 그 지점으로 이동하고 근처에서 감속해 멈춘다. 이동 중에 다시 찍으면 이전 목표는 취소되고 새 지점으로 바로 바뀐다(방향키 이동 중이어도 목표 이동으로 바뀐다). 클릭한 지점에는 물결 띠 두 개가 시차를 두고 바깥에서 안쪽으로 모여들며 사라지는 효과를 보여 준다(약 0.9초, `prefers-reduced-motion`이면 제자리에서 옅어지는 링 하나).
  - 모바일(터치) 이동 방식은 두 가지이고 메뉴의 [이동 방식](태블릿은 도구 줄의 🕹/👆 버튼)으로 바꾼다. 고른 방식은 그 브라우저에 기억한다.
    - 조이스틱(기본): 누른 자리에 조이스틱 판(반지름 56px)이 생기고, 손가락을 끈 방향으로 움직인다. 판 반지름만큼 끌면 최대 속도이고 덜 끌면 그만큼 느리다(8px 안쪽은 멈춤). 떼면 감속해 멈춘다. 서버에는 방향키와 같은 방향 입력(-1~1)으로 초당 20회까지 보낸다. 두 번째 손가락은 무시한다.
    - 터치 이동: 마우스 클릭과 같다(누른 지점으로 가고, 누르고 있으면 계속 따라간다).
  - 방향키·WASD: 직접 이동. 목표를 해제한다. 누르고 있는 동안에는 1초마다 지금 방향을 다시 보내서 중간에 입력 하나가 빠져도 서버가 곧 같은 상태로 돌아온다. 창을 벗어나거나 Ctrl·Alt·Cmd 조합을 누르거나 입력창으로 옮기면 누르던 방향키를 모두 뗀 것으로 본다. Ctrl·Alt·Cmd와 함께 누른 방향키는 이동에 쓰지 않는다. 서버 방에 들어가기 전이나 연결이 끊긴 동안에는 이동 입력을 받지 않고, 다시 연결되면 아직 누르고 있는 방향을 다시 보낸다.
  - 다른 플레이어 정보(4.11): PC는 그 원을 **우클릭**(브라우저 메뉴는 뜨지 않는다). 모바일은 터치·드래그가 모두 이동이라 동작으로는 겹치므로, 도구 줄의 [🔍]을 누른 뒤 원을 탭한다(이 모드에서는 탭해도 이동하지 않고, 원이 아닌 곳을 누르면 모드만 꺼진다. 위쪽에 "정보를 볼 원을 누르세요" 안내). [🔍]은 터치 기기에서만 보인다. 손가락으로도 누르기 쉽게 화면에서 반지름 14px보다 작은 원은 14px로 본다.
  - 누르고 있기(마우스 왼쪽 버튼·손가락): 누르고 있는 동안 그 자리로 계속 따라간다. 누른 채 움직이면 목표도 같이 움직이고, 가만히 누르고 있어도 화면이 따라 움직이므로 0.1초마다 그 자리를 다시 찍는다. 떼면 마지막 지점에서 감속해 멈춘다. 클릭 이동은 초당 10회까지(세밀하게 방향을 바꿀 수 있게) 서버로 보낸다. 방향키는 누르고 떼고 방향을 바꿀 때마다 바로 보내고(한 프레임 16ms 안의 변화만 하나로 합친다), 짧게 톡 눌렀다 떼도 뗀 순간 바로 멈춘다. 그 사이에 찍은 지점은 버리지 않고 마지막 지점을 보낸다.
- 충돌 후 목표: 밀어낸 큰 쪽은 유지, 밀려난 작은 쪽은 해제, 비슷한 크기라 같이 튕기면 둘 다 해제.
- 정지: 조작하지 않으면(창 포커스를 잃어도) 감속해서 그 자리에 멈춘다. 자동으로 떠다니지 않는다.
- 시점: 내 아이콘을 항상 화면 가운데에 둔다. 아이콘이 커질수록 화면을 조금씩 줌아웃한다(배율 = 1 / (1 + (반지름 − 16) / 170), 반지름 45px → 0.85, 104px → 0.66, 308px → 0.37, 600px → 0.23). 배율은 반지름처럼 0.5초에 걸쳐 부드럽게 바뀐다. 아레나 바깥은 어둡게 칠하고 벽 경계선을 그린다.
- 화면 크기 보정: 위 시점의 줌 배율에 화면 배율(화면 짧은 변 / 720px, 0.6~1)을 곱하고, 내 원의 지름이 화면 짧은 변의 25%를 넘지 않게 더 줌아웃한다. 데스크톱은 거의 그대로이고, 휴대폰(짧은 변 390px)에서는 유행도 1,000일 때 원이 화면 너비의 58% → 25%로 줄어 주변이 보인다.
- 바닥 격자: 50px마다 1px 선, 250px마다 2px 선. 짙은 회청색 바닥에 약 15% 투명도의 밝은 선. 아레나 바깥에는 격자가 없다.
- 가시성: 모든 아이콘에 테두리와 옅은 그림자를 그린다. 바닥과 대비가 낮은 색은 고를 수 없고 색에 투명도를 받지 않는다. 내 아이콘에는 흰색 링을 하나 더 그린다.
- 크기 변화는 0.5초에 걸쳐 부드럽게 바뀐다.
- 방: 나라마다 하나, 최대 1000명이다. 차면 입장을 막고 대기열은 두지 않는다. 월드는 1000명 기준 약 48,000×48,000px이고 인원이 적으면 활동 영역을 좁힌다(한 변 = 기준 맵 × √(인원 / 1000), 가장 좁을 때 기준 맵 한 변의 1/4 = 12,000px). 영역은 인원이 늘면 바로 넓어지지만 줄 때는 한 변이 초당 `area_shrink_speed`(기본 60px)씩만 줄어든다(사람이 한꺼번에 나가거나 서버를 다시 켜도 원이 가장자리로 한꺼번에 밀려나지 않게). 밀도가 낮은 곳에 스폰한다. 나간 뒤 5분 안에 다시 들어오면(새로고침, 연결 끊김 포함) 새 자리 대신 마지막 위치에서 이어 가고, 입장 보호도 다시 받지 않고 남은 보호 시간만 이어 간다(새로고침으로 자리를 바꾸거나 보호를 다시 받는 악용 방지). 5분이 지나면 기록을 버리고 새로 스폰한다. 서버를 다시 시작해도 이어 간다: 접속 중인 사람의 위치와 활동 영역을 30초마다와 서버를 끌 때 저장해 두고(`player_positions`, `room_states`), 다시 켠 뒤 5분 안에 들어오면 그 위치에서 시작하며(입장 보호를 받는다) 활동 영역도 저장해 둔 크기에서 시작해 서서히 줄어든다. 미니맵에 큰 아이콘 상위 20명과 내 위치를 보여 준다. 서버는 미니맵 목록을 1초마다 보내지만, 점의 위치는 게임 화면과 같은 스냅샷(초당 10번, 보간)으로 그려 부드럽게 움직인다(스냅샷에 없는 원은 1초 사이를 이어 그린다).

### 4.3 충돌

| 상황 | 결과 |
|---|---|
| 반지름 비율 1.15 미만 | 서로 반발하며 같이 튕긴다 |
| 비율 1.15 이상 | 작은 쪽만 충돌 방향으로 크게 튕긴다. 큰 쪽은 반동 없음 |
| 튕김 세기 | 밀려나는 거리 = 최대 속도 × 0.6초 × 세기(같은 크기끼리 세기 1, 작은 쪽은 반지름 비율만큼, 상한 3배). 최대 속도 480px/s면 같은 크기끼리 288px, 크기 차이가 크면 최대 864px. 0.5초 동안 처음에 빠르고 점점 느려진다(속도 ∝ 남은 시간²). 밀려난 사람의 화면 예측도 같은 식으로 같이 밀린다 |
| 같은 상대 연속 충돌 | 0.5초 쿨다운 |
| 최대 속도 | 크기와 관계없이 모든 아이콘이 같다(기본 480px/s, DB 설정값). 충돌의 결과는 크기가 가른다 |

- 튕겨도 탈락하지 않는다. 가장자리는 벽이고 추락 구역은 없다.

충돌로 키워드 잃기
- 두 플레이어가 부딪히면 현재 유행도가 낮은 쪽이 보관함 중 하나를 무작위로 잃는다. 크기(반지름 비율)와 관계없이 점수만 비교하고, 점수가 같으면 아무도 잃지 않는다.
- 잃는 후보: 보관함 중 금지되지 않은 키워드 전부(💤 키워드 포함). 후보가 없으면 아무 일도 없다.
- 잃은 키워드는 목록에서 바로 지워지고 점수에서 빠진다. 바로 다시 `+`할 수 있고, 그때의 점수로 새로 더해지며 24시간도 새로 시작한다. 잃은 키워드를 다시 찾아 `+`하는 것 자체를 상호작용으로 본다.
- 잃은 사람에게는 어떤 키워드를 몇 점짜리로 잃었는지 알린다("민수와 부딪혀 '양쯔깐루' 21점짜리 키워드를 잃었어요", 내 원 위에 −21). 점수는 잃는 순간 그 키워드가 더해 주던 값이다(💤면 0점).
- 사람끼리 부딪혀 이기면 진 사람이 잃은 키워드를 **빼앗는다**. 그 키워드가 내 보관함에 없으면 일반 추가와 같이 들어가고(24시간 유지, EXP +1, 가진 사람 수 그대로 유지, 점수 반영), 이미 있으면 남은 시간만 지금부터 다시 24시간으로 늘어난다(점수·EXP는 그대로). 잃은 사람에게는 어떤 키워드를 몇 점짜리로 잃었는지 보여 준다("민수에게 '양쯔깐루' 21점짜리 키워드를 빼앗겼어요"), 이긴 사람에게는 키워드와 점수를 보여 준다("민수의 '양쯔깐루' 21점을 빼앗아 보관함에 넣었어요!" / "…' 키워드를 빼앗아 갱신하였어요!").
- 봇에게 지면 키워드를 잃기만 하고(봇은 실제 키워드를 갖지 않는다), 봇을 이기면 봇의 키워드 대신 그 나라 🔥 키워드 중 하나를 무작위로 얻는다("Bot을 이겨 '양쯔깐루' 12점 키워드를 얻었어요!"). 이미 가진 키워드가 나오면 사람에게서 빼앗을 때처럼 남은 시간만 24시간으로 늘린다(4.21).
- 보호 장치
  - 키워드를 잃은 쪽(사람·봇)은 상대와 관계없이 3초 동안 무적이다(다시 잃지 않는다). 연속으로 털리는 것을 막는다. 무적인 동안 그 원에 하늘색 보호막과 남은 초(🛡 3, 2, 1)가 모두의 화면에 보인다.
  - 입장 직후 10초 동안은 잃지 않는다.
  - NPC 봇에게 져도 키워드를 잃는다. 봇이 지면 봇은 키워드 대신 점수를 잃는다(4.21).
- 보호 시간은 관리자 설정이다(13.3).
- 판정은 항상 원의 반지름으로만 한다. 꾸미기는 판정에 영향이 없다.

### 4.4 키워드 검색과 `+`
1. 검색창에 입력하고 Enter 또는 검색 버튼을 누른다. 자동완성·추천은 없다.
2. 서버가 키워드를 정규화(4.18)해서 현재 나라에서 찾는다. 다른 나라의 같은 단어는 별개 키워드다.
   - ⛔금지: "검색할 수 없는 키워드예요"
   - 🔥활성·💤비활성: 결과 카드를 바로 보여 준다. 💤 키워드는 외부 소스를 다시 조회해서 외부에서 확인되면(관심도 10 이상) 그 자리에서 🔥활성으로 바꾼다.
   - DB에 없음: 외부 소스를 바로 조회한다. 확인되면 🔥활성 키워드로 등록하고, 아니면 다른 키워드와 같은 💤 카드와 `+` 버튼을 보여 준다. 첫 `+` 때 키워드를 만든다(4.6).
3. 결과 카드: 키워드명, 상태 배지(🔥활성/💤비활성/⛔금지), `67점 · 👥 1,204명`(트렌드 값은 "트렌드 67"이 아니라 "67점"으로 쓴다), 시간별 활동 그래프, 댓글, `+` 버튼(4.12). 트렌드 값(0~100)은 키워드의 현재 세기이고 👥 인원은 지금 이 키워드를 가진 사람 수다. `+` 버튼은 화면에 [추가]로 쓴다. 이미 가진 키워드는 그 자리에 [보유중]을 보여 주고, 사라지기까지 남은 시간(`23시간 12분 남음`)을 함께 보여 준다. 활성 조건 같은 규칙 설명은 카드에 쓰지 않고 가이드·FAQ(4.17)에 둔다.
4. `+`하면 보관함에 들어가고 그 키워드의 점수만큼 현재 유행도가 바로 올라 아이콘이 커진다. 아이콘 위에 `+N`이 뜬다. 💤 키워드는 `+`할 수 있지만 🔥가 되기 전까지 키워드 점수는 0점이다. EXP는 💤 키워드에도 바로 받는다(4.9).
5. 검색과 `+`는 그 키워드의 누적 카운터에 센다(9.9). 검색은 검색한 플레이어의 누적 검색 횟수(`players.search_count`)도 +1 한다(찾았는지·금지인지와 관계없이, 형식에 맞지 않아 거절된 입력은 제외). 내 정보 창에 보인다.

### 4.5 보관함
내가 `+`한 키워드 목록이다. 하루 단위의 빠른 주기로 게임이 흘러가게 하기 위해 다음 규칙을 둔다.
- 같은 키워드는 한 번만 `+`한다. 목록에 있는 동안 그 키워드의 `+` 버튼은 비활성화된다.
- `+`한 지 24시간이 지나면 목록에서 자동으로 삭제되고, 그 뒤에는 다시 `+`할 수 있다. 충돌로 잃은 키워드(4.3)도 바로 지워진다.
- 목록 위에 지금 가진 키워드 개수(`players.hold_count`)를 보여 준다. 항목마다 키워드, 상태 배지, `+`한 시각, 지금 트렌드 값과 점수, 삭제까지 남은 시간(1시간 이내면 강조)을 보여 준다. 기본 정렬은 남은 시간이 많은 순(`player_keywords.expires_at` 내림차순, 곧 사라질 키워드가 아래)이다. 목록 위의 정렬 칩 [남은 시간] [최신순] [키워드] [상태] [트렌드 점수] 중 하나를 누르면 그 기준(키워드는 가나다, 상태는 🔥 → 💤)으로 정렬하고, 고른 칩에 ↑↓로 방향을 보여 준다. 고른 칩을 다시 누르면 방향이 바뀐다. 기준을 바꾸면 그 기준에서 자연스러운 방향(트렌드 점수는 높은 것부터, 남은 시간은 많은 것부터)으로 시작하고, 값이 같으면 최신순이다. 고른 정렬은 그 브라우저에 기억한다. 즐겨찾기·폴더·메모는 없다.
- 삭제된 `+`의 기록은 남지 않는다. 누적 `+` 횟수(`total_plus_count`), EXP, 댓글 점수는 누적값으로 남고, 키워드 쪽에는 누적 `+` 수와 누적 검색 수가 남는다(9.9).
- 키워드가 ⛔금지되면 모든 사용자의 목록에서 조회되지 않고 점수 산정에서 제외된다(데이터는 그대로 둔다).

### 4.6 새 키워드
검색해도 없는 신조어·밈도 별도 등록 절차 없이 `+`할 수 있다.

흐름
1. 검색 결과가 없거나 외부 관심도가 10 미만이면 💤 카드와 `+` 버튼을 보여 주고(4.4), 첫 `+` 때 키워드가 💤비활성으로 만들어진다. 💤 키워드도 누구나 `+`할 수 있고 키워드 점수만 0점이다.
2. 그 키워드를 가진 사람이 3명이 되거나(내부 확산) 외부 관심도 10 이상이 확인되면(외부 확인) 즉시 🔥활성이 된다. 둘 중 하나만 충족하면 된다.
3. 🔥가 되는 순간 키워드를 가진 사람(💤일 때 `+`해서 아직 24시간이 안 지난 사람)은 즉시(접속 중이 아니면 최대 1분 안에) 그 키워드의 점수를 받는다. 외부에서 확인된 키워드는 가진 사람이 없어도 기본 점수를 받고, 사람만으로 활성된 키워드는 3명이 모여야 점수가 생긴다. 반영값은 지금 모든 소스가 1이라 같은 인원이면 점수도 같다(4.8). 사람 수에 따른 증가가 완만해서 여러 계정 담합으로 얻는 점수가 작다.
4. 외부 데이터에 없고 가진 사람도 3명 미만이 되면 💤비활성이 된다(4.7).

등록 조건
- 게스트를 포함한 모든 사용자, 비용·한도 없음.
- 20자 이하(입력한 글자 기준). 최소 길이 제한은 없어서 한 글자 키워드도 된다. 영문·숫자·공백과 지원 언어의 문자(한글, 가나, 한자, 데바나가리). 그 지역 문자가 아니어도 된다.
- 정규화(4.18) 뒤에도 한 번 더 검사한다: 허용 문자만 남았는지, 비어 있지 않고 100자 이하인지(NFKC가 `㈱` → `(株)`처럼 글자를 늘리거나, 공백만 있는 입력이 비는 경우를 거른다). 통과하지 못하면 거부한다.
- URL·전화번호·이메일 등 개인정보 패턴, 차단어, 민감 키워드, 실존 인물 이름 패턴은 쓸 수 없다.

### 4.7 키워드 생존주기

```
(없음) ──검색, 외부 관심도 10 이상──→ 🔥활성 (반영 소스 = 그 외부 소스)
(없음) ──첫 `+`(외부 데이터 없음 또는 10 미만)──→ 💤비활성 (반영 소스 = internal)
💤비활성 ──가진 사람 3명 이상 또는 외부 관심도 10 이상──→ 🔥활성 (즉시)
🔥활성 ──외부 데이터가 사라짐──→ 반영 소스가 internal로 바뀜. 가진 사람 3명 미만이면 💤비활성 (즉시)
어느 상태든 ──관리자 금지──→ ⛔금지 ──해제──→ 💤비활성
```

| 상태 | 의미 | `+` | 검색 | 점수 |
|---|---|---|---|---|
| 💤 비활성 | 아직 활성 전이거나, 외부 데이터에서 사라지고 가진 사람도 3명 미만이라 잠든 키워드 | O | O | 0점 |
| 🔥 활성 | 외부 관심도 10 이상 또는 가진 사람 3명 이상 | O | O | O |
| ⛔ 금지 | 관리자가 금지한 키워드 | X | X | 제외 |

- 상태는 `keyword_states` 테이블(활성 / 비활성 / 금지)로 구분한다. 애플리케이션이 시작할 때 이름으로 번호를 찾아 두고 코드에서 상수로 쓴다. 새 상태는 이 테이블에 행을 추가하고 전이 코드를 쓰면 된다.
- 키워드는 지우지 않는다. 같은 단어는 항상 같은 키워드로 이어져 활동 기록·댓글이 남는다. 개인정보·법적 문제가 있을 때만 관리자가 완전히 지운다.
- 반영 소스(`keywords.data_source_id`)는 점수의 가중치를 정하는 소스다. 외부 데이터에서 확인되면 그 나라의 외부 소스(KR은 구글 실시간 인기 `google`), 관리자가 넣었으면 `admin`, 아니면 `internal`이다(10.3).
- 💤 → 🔥 전환은 `+`할 때(인원 확인), 검색 때 외부 재조회, 구글 실시간 인기 목록에 오를 때(5분마다) 판정하고 바로 바꾼다.
- 🔥 → 💤 전환은 한 가지 경로뿐이다: 반영 소스가 외부였던 키워드의 외부 유지 기간(기본 7일, 10.2)이 끝났는데 목록에 없고 가진 사람도 3명 미만일 때. 유지 기간 안에는 `+`가 오래 없어도 🔥를 유지한다. 거대 플랫폼의 외부 데이터를 사용자 수보다 무겁게 본다는 원칙이다. 판정 시점은 유지 기간이 끝날 때와 가진 사람 수가 줄 때(24시간 삭제, 충돌로 잃기)다.
- 유행이 식는 것은 별도 상태가 아니라 가진 사람 수 감소로 나타난다. 외부 키워드의 점수는 기본값 아래로 내려가지 않는다(4.8).
- 금지된 키워드는 보관함과 댓글 데이터를 지우지 않고, 조회되지 않게 하고 점수 산정에서 제외한다. 해제하면 💤비활성으로 돌아간다.

### 4.8 점수
이 절의 숫자는 모두 기본값이고 관리자가 바꿀 수 있다(13.3).

키워드 트렌드 값 (`keywords.trend_value`, 0~100)

```
P           = 그 나라 활동 인원: 만료 전 키워드를 하나 이상 가진 플레이어 수(접속하지 않은 사람 포함, 봇·탈퇴 제외)
x           = min(1, (n / max(P, 20)) / 0.5)                    // n = 가진 사람 수. 가진 비율 50%에서 1
g(x)        = log10(1 + x / 0.3) / log10(1 + 1 / 0.3)           // 0에서 0, 1에서 1
trend_value = 🔥활성이면 round( w × ( 3 + 47 × g(x) ) ), 💤·⛔이면 0   // 정수로 반올림(0.5는 올림). DB도 정수(INT)
              w = 반영 소스의 가중치(0~2, 지금은 모든 소스 1)
키워드 점수  = trend_value                                       // 키워드 하나가 더하는 점수. 트렌드 값과 같다. 3~50(w=1)
```

| 가진 비율 | 0% | 1% | 2% | 5% | 10% | 20% | 30% | 40% | 50% 이상 |
|---|---|---|---|---|---|---|---|---|---|
| trend_value(w=1) | 3 | 5 | 7 | 12 | 19 | 30 | 38 | 45 | 50 |

| 활동 인원 P | 가진 사람 1 | 3 | 5 | 10 | 25% | 50% |
|---|---|---|---|---|---|---|
| 20명 이하(최소 인원 20으로 계산) | 12 | 25 | 34 | 50 | 34 | 50 |
| 100명 | 5 | 9 | 12 | 19 | 34 | 50 |
| 1,000명 | 3 | 4 | 4 | 5 | 34 | 50 |

- 고정 인원이 아니라 비율로 정해서, 활동 인원이 10명이든 1,000명이든 "4분의 1이 가진 키워드"는 같은 34점이다. 인기 있는 키워드 하나가 흔한 키워드 여럿보다 값지다(100명일 때 40명이 가진 키워드 45점, 1명만 가진 키워드 5점).
- 50%(최고점 비율)를 넘게 몰려도 점수는 그대로라서, 모두가 같은 키워드로 몰려가는 이득을 제한한다.
- 최소 인원(20): 활동 인원이 적을 때 한두 명이 큰 비율이 되는 것을 막는다. 20명 이하에서는 20명으로 계산해서, 가진 사람 1명 12점, 10명 이상이면 최고점이다.
- 로그 완만도(0.3)는 작을수록 처음 몇 명에서 크게 오르고, 클수록 비율에 비례한다.
- 외부에서 확인된 키워드는 가진 사람이 없어도 3점에서 시작해서 첫 `+`가 0점이 되지 않는다. 사람만으로 활성된 키워드는 3명이 되어야 시작한다. 반영값이 모두 1이라 🔥가 된 뒤의 점수는 반영 소스와 관계없이 가진 비율로만 정해진다. 키워드 점수가 트렌드 값과 같으므로 화면에는 트렌드 값 하나만 보여 준다.
- 식의 3은 기본 비율, 50은 최대 기준값이다. 가중치가 최대 2라서 trend_value는 구조적으로 100을 넘지 않는다(지금은 모두 1이라 최대 50).
- 외부 데이터의 크기(순위·상대 비율)는 점수에 들어가지 않고 외부 확인(관심도 10 이상)과 반영 소스를 정하는 데만 쓴다.
- 트렌드 값은 가진 사람 수(`holder_count`)가 바뀔 때(`+`, 24시간 삭제, 충돌로 잃기), 반영 소스나 상태가 바뀔 때 바로 다시 계산해서 저장한다. 활동 인원은 1분마다 다시 세고, 그때 모든 🔥 키워드의 값을 지금 식으로 구해 달라진 것만 고친다(관리자 설정 변경도 여기서 반영된다). 그래서 내가 아무것도 하지 않아도 활동 인원이 늘면 같은 인원이 가진 키워드의 점수가 조금 내려간다.

현재 유행도 (플레이어 점수. 아이콘 크기를 정하는 값, `players.current_score`)

```
현재 유행도 = min(EXP, 100) + Σ 보관함의 점수   // 키워드는 🔥활성만, 💤·⛔는 0. 모두 정수라 유행도도 정수(DB INT)
```

- `+`하는 순간 EXP +1과 그 키워드의 새 점수가 바로 더해진다. EXP 점수는 줄지 않아서, 오래 플레이한 사람은 키워드가 모두 만료돼도 100점(반지름 최소 약 45px)이 남는다.
- 내가 `+`한 키워드에 사람이 몰리면 내 원도 함께 커지고 사람이 빠지면 작아진다. 키워드의 트렌드 값이 바뀌면 그 키워드를 가진 접속 중인 모든 플레이어의 점수와 원 크기가 실시간으로 바뀐다(9.2). 접속 중이 아닌 플레이어는 DB에서 1분 안에 다시 합산하고, 1시간마다 전원을 점검한다(9.4).
- 매일 새 유행을 찾아 `+`해야 크기를 유지한다. `+` 횟수 제한(에너지, 슬롯)은 없다. 점수가 무한히 쌓이지 않게 하는 장치는 24시간 삭제, 같은 키워드 1회, 💤 키워드 0점, EXP 점수 상한 100, 크기 상한이다.

크기

```
radius    = 16 + 584 × min(현재 유행도, 2000) / 2000    // px. 최대 600px = 지름 1,200px = 기준 맵 한 변(48,000px)의 2.5%
zoom      = 1 / (1 + (radius − 16) / 170)               // 화면 배율(4.2)
```

| 현재 유행도 | 0 | 100 | 300 | 600 | 1,000 | 2,000 이상 |
|---|---|---|---|---|---|---|
| 반지름 | 16px | 45px | 104px | 191px | 308px | 600px |
| 지름 / 맵 한 변 | 0.07% | 0.2% | 0.4% | 0.8% | 1.3% | 2.5% |
| 키워드 20점 `+` 한 번 | +36% | +13% | +5.6% | +3.1% | +1.9% | 변화 없음 |

- 점수 1점에 반지름 0.292px이다. 키워드 점수 15점짜리 `+`는 약 4px, 50점짜리는 약 15px 커진다. 작을 때는 키워드 하나로 크게 변하고, 클 때는 키워드가 여러 개 겹쳐 바뀔 때 눈에 띈다.
- 최대 속도는 크기와 관계없이 모든 플레이어가 같고(기본 480px/s) `settings`의 값이다(13.3). 줌아웃 때문에 화면에서는 큰 아이콘이 더 천천히 움직여 보인다.
- 상한은 현재 활동 영역이 아니라 기준 맵(48,000px)으로 고정해서 인원이 바뀌어도 모두의 크기가 한꺼번에 바뀌지 않는다. 상한(2,000점)은 EXP 점수 100에 점수 50짜리 키워드 약 38개를 더한 값이고, 베타에서 실제 점수 분포를 보고 조정한다.

### 4.9 레벨, 성장 아이콘, 꾸미기

레벨과 EXP (플레이어 단위, 나라마다 따로, 줄지 않음)
- EXP는 `+` 횟수로만 쌓인다. `+` 한 번 = 1 EXP이고 `+`한 순간 바로 준다(💤 키워드 포함). 다른 행동으로는 주지 않는다. 즉각 반응을 주고 활동량을 늘리려는 선택이다.
- 레벨은 1~100이다. 레벨별 필요 누적 EXP는 DB의 `levels` 테이블에 두고 관리자가 바꾼다(13.4). 기본값은 다음과 같다.

| 레벨 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10 |
|---|---|---|---|---|---|---|---|---|---|
| 누적 EXP | 1 | 3 | 8 | 13 | 22 | 33 | 50 | 72 | 100 |

| 레벨 | 11 | 20 | 30 | 50 | 70 | 100 |
|---|---|---|---|---|---|---|
| 누적 EXP | 121 | 400 | 900 | 2,500 | 4,900 | 10,000 |

- 11~100레벨은 `100 × (레벨 / 10)²`를 반올림한 값이다. 하루 `+` 100번이면 30레벨까지 약 9일, 100레벨까지 약 100일이다(가정치).
- EXP는 현재 유행도에도 들어간다: `min(EXP, 100)`(4.8). 100 EXP(10레벨)에서 상한이고, 그 이상은 레벨만 오른다.
- 레벨이 오르면 알림을 보여 준다. 정보 팝업과 내 정보에 레벨과 다음 레벨까지 남은 EXP를 보여 준다. 새 나라에서는 1레벨부터 시작한다.

성장 아이콘 (1~10단계)
- 모든 플레이어는 같은 캐릭터가 레벨에 따라 자라는 아이콘을 쓴다. 캐릭터는 지금은 거북이로 시작한다(동물이나 밈 캐릭터로 바꿀 수 있다, 16.2). 1레벨은 단순한 테두리와 단일 배경색이라 얼굴처럼 보이지 않고, 레벨이 오를수록 눈·코·입 같은 부위와 캐릭터의 형태가 흐릿하게 생기다가 점점 선명해져 10레벨에서 뚜렷하게 완성된다. 얼굴 부위는 원 안에만 그린다. 11레벨 이후는 모습이 그대로이고 레벨 숫자만 오른다.
- 바탕색은 그 캐릭터에 맞춰 정해진 색 하나다(무작위가 아니다). 그래서 꾸미기가 열리기 전(11레벨 전)에는 같은 레벨의 모든 사용자가 같은 모습이고, 닉네임과 내 아이콘의 흰색 링(4.2)으로 구분한다.
- 거북이는 위에서 내려다본 모습이다. 부위가 생기는 레벨: 2 등껍질 → 3 가운데 무늬 → 4 바깥 무늬 → 5 머리 → 6 눈 → 7 앞발 → 8 뒷발·꼬리 → 9 웃는 입·볼 → 10 등껍질 광택(완성). 새 부위는 흐릿하게(진하기 25%) 생겨 10레벨까지 점점 진해진다.
- 10레벨까지는 레벨이 오를 때 새 부위가 그려지는 연출을 보여 준다.
- 레벨 표시 옆 아이콘: 아레나의 원과 별개로, 레벨 글자 왼쪽(아래 내 정보 줄, 내 정보 창, 다른 플레이어 정보 팝업의 "레벨")에 그 레벨의 성장 거북이 아이콘을 작게 붙인다(예전의 🐢 이모지 대신). 아이콘의 바탕은 레벨 구간으로 정한다.
  - 1~10레벨: 기본 거북이 색(바탕색 없음).
  - 11~99레벨: 10레벨 구간(11~19, 20~29, … 90~99)마다 바탕색이 바뀌고(파랑 → 청록 → 초록 → 연두 → 노랑 → 주황 → 빨강 → 분홍 → 보라), 일의 자리가 0에서 9로 갈수록 같은 색이 옅은 것(진하기 30%)에서 진한 것(100%)으로 짙어진다.
  - 100레벨: 바탕이 무지개 그라데이션.
  - 값은 `levels`의 `badge_color`(#RRGGBB, NULL이면 기본 색)·`badge_alpha`(진하기 0~100%)·`badge_rainbow`에 있고, 위 규칙은 처음 넣는 기본값(시더)이다. 운영에서 DB 값을 고치면 1분 안에 반영된다. 프론트는 `GET /api/levels/badges`로 받아 한 번만 불러 둔다.

꾸미기 프로필 (11레벨부터, 해금 레벨은 설정값)

| 항목 | 내용 | 대상 |
|---|---|---|
| 바탕색·테두리 | 프리셋 24색 + 직접 선택(HEX), 테두리 색, 두께 1~8단계 | 11레벨 이상 모든 사용자 |
| 이름표 | 닉네임 글자색, 모양(기본 / 리본 / 빛) | 11레벨 이상 모든 사용자 |
| 원 안에 그릴 것 | 🐢 성장 캐릭터 / 🎨 직접 그린 픽셀 그림(32×32, 32색) | 그림은 11레벨 이상 로그인 사용자 |
| 테두리 효과 | 아래 표의 5가지(효과 목록 `effects`, 종류 BORDER) | 11레벨 이상 로그인 사용자 |
| 이동 효과 | 4.23의 12가지(종류 TRAIL) | 11레벨 이상 로그인 사용자 |
| 직접 올린 이미지(아직 없음) | | 11레벨 이상 로그인 사용자 |

- 꾸미기는 플레이어마다 **프로필 1~3번 칸**(`profiles`, `(player_id, slot)` 유일)으로 관리한다. 칸마다 위 항목을 모두 담는다: 바탕색, 테두리 색·두께, 이름표 글자색·모양, 원 안에 그릴 것(`profile_type`: `GROWTH` / `PIXEL`)과 그 칸의 픽셀 그림, 이동 효과(`trail_effect_id`), 테두리 효과(`border_effect_id`). 색은 모두 HEX, null이면 기본값이다. 프리셋 24색은 DB가 아니라 설정(코드)으로 관리한다.
- **장착**: 한 칸만 장착하고(`equipped`), 아레나와 자랑하기 카드는 장착한 칸의 모습이다. 저장한 칸이 하나도 없으면 1번 칸(기본 모습: 성장 캐릭터, 정해진 바탕색)을 장착한 것으로 본다. 처음 저장하는 칸이 1번이면 그 칸이 장착된다.
- **꾸미기 창**(내 정보 → [🎨 꾸미기]): 위에 1~3번 칸 탭(칸마다 작은 미리 보기와 "장착 중"/"저장됨"/"기본 모습"), 그 아래 큰 미리 보기, 항목별 고르기, 맨 아래 [되돌리기]·[저장]·[저장하고 장착](장착 중이 아닌 칸) 또는 [이 프로필 장착](바꾼 것이 없을 때).
  - 칸 탭과 큰 미리 보기는 창 위에, 버튼 줄은 창 아래에 고정하고 그 사이의 항목 고르기만 스크롤한다. 항목을 바꾸면서 같은 화면에서 미리 보기를 바로 본다. 좁은 화면에서는 칸 탭을 한 줄에 작게 두고 미리 보기 높이를 화면의 1/4 정도로 줄인다.
  - 고르는 동안은 **미리 보기에만** 보인다. 미리 보기는 작은 아레나에서 원이 8자로 돌며 고른 이동 효과를 남기고, 바탕색·테두리·테두리 효과·이름표(내 닉네임)·그림을 아레나와 같은 그림 코드로 보여 준다(`prefers-reduced-motion`이면 멈춘 한 장).
  - [저장]해야 그 칸에 들어간다(`PUT /api/me/profiles/{slot}`). 장착한 칸이면 접속 중인 방의 원과 이동 효과가 바로 바뀐다. 저장하지 않고 다른 칸으로 넘어가면 한 번 묻는다.
  - 효과는 설명 없이 이름만 칩으로 보이고, 잠긴 효과는 🔒와 조건 안내(마우스를 올리면)만 보인다. 게스트는 그림·효과 칸에 로그인 안내와 [Google로 로그인]이 있다.
  - 11레벨 전에는 장착한 모습의 미리 보기와 잠금 안내만 보인다.
- 서버 검사(저장): 11레벨 전 403 `CUSTOMIZE_LOCKED`. 바닥색(#1f2a37)과의 명도 대비가 1.6 미만인 바탕색·이름표 글자색은 거절, 두께 1~8단계, 이름표 모양은 `RIBBON`·`GLOW`만. 효과는 효과 규칙(4.23)으로 확인하되 그 칸에 이미 고른 효과는 그대로 둘 수 있다. 저장·장착은 5초에 1번(`LOOK_TOO_FAST`).
- 픽셀 그림: [✏️ 그림 그리기]로 편집기를 열고 맨 아래 [저장]을 누르면 그 칸의 미리 보기에 들어가고([취소]는 그림을 버리고 프로필 화면으로 돌아간다, 두 버튼은 같은 크기에 색만 다르다), 프로필을 저장할 때 함께 저장된다. 칸마다 그림을 하나씩 가진다.
  - 편집기: 펜·지우개·채우기·스포이드(단축키 B·E·G·I), 붓 크기 1~3칸, 좌우 대칭, 되돌리기·다시 하기(Ctrl+Z·Ctrl+Y, 60단계), 한 칸씩 옮기기·좌우 뒤집기·전체 지우기, 격자 켜고 끄기, 프리셋 24색 + 어두운 색 6개 + 직접 선택 + 최근 쓴 색. 옆에 아레나에서 보이는 크기 세 가지(96·44·20px)로 미리 보기를 둔다. 휴대폰에서는 손가락으로 끌어 그린다.
  - 그림은 파일이 아니라 값으로 DB에 둔다(`profiles.pixel_palette` 쓴 색 목록, `pixel_data` 칸마다 한 글자). 서버가 형식을 검사하고 쓰지 않은 색은 뺀다. 빈 그림은 저장할 수 없고, 원 안에 그림을 고르려면 그 칸에 그림이 있어야 한다(`ART_NONE`).
  - 보이기: 서버가 값으로 32×32 PNG를 그려 `/api/art/{프로필 번호}.png?v={그림을 바꾼 시각}`으로 준다(로그인 없이, 1년 캐시). 그림을 바꾸면 주소가 바뀌어 옛 그림이 캐시에 남지 않는다. 방 명단(`roster`)의 `art`에 이 주소가 실리고, 아레나는 원 안으로 잘라 칸이 또렷하게(보간 없이) 키워 그린다. 받기 전에는 성장 캐릭터를 그린다.
  - 제한: 그림은 바꾼 뒤 `art_change_minutes`(기본 10분)가 지나야 다시 바꿀 수 있다(모든 칸을 합쳐 센다, `profiles.image_changed_at`). 게스트 403 `ART_LOGIN`, 그림 저장 정지(13.5) 403 `ART_BANNED`.
  - 자동 검열은 하지 않는다(칸 그림이라 사진·실물 이미지가 들어가기 어렵다). 신고(플레이어 신고, 13.5)와 관리자 꾸미기 초기화(13.10)로 대응한다.
- 이미지 업로드(아직 없음): PNG·JPG·WebP 최대 2MB → 원형 크롭 → 서버가 128×128 WebP로 줄이고 메타데이터 제거, 원본은 보관하지 않는다. 투명한 부분은 바탕색으로 채운다. 자동 검열(13.5)을 통과해야 저장한다. 변경은 1시간에 1번이다.
- 테두리 효과: 기본 테두리 위·바깥에 움직이는 효과다. 크기는 반지름에 비례해 큰 원도 같은 모습이다. 아레나·미리 보기가 같은 그림(`game/skin.ts`)을 쓴다.

| 코드 | 이름 | 모습 |
|---|---|---|
| `glow` | 은은한 빛 | 테두리 둘레에 테두리 색 빛이 숨 쉬듯 번진다 |
| `dash` | 도는 점선 | 테두리 바깥에 점선 고리가 천천히 돈다 |
| `gradient` | 그라데이션 | 바탕색과 테두리 색이 섞인 굵은 테두리가 돈다 |
| `pulse` | 맥박 | 테두리에서 고리가 퍼져 나가며 옅어진다(1.6초에 두 번) |
| `rainbow` | 무지개 | 무지개색 테두리가 흐른다 |

- 이름표: 글자색과 모양(기본 검은 외곽선 / 리본: 테두리 색 둥근 띠 바탕 / 빛: 글자 둘레에 글자색 빛). 봇은 꾸미지 않는다. 칭호(4.10)는 그대로 노란 글씨다.
- 게스트가 로그인하지 않은 채 저장한 칸에는 효과·그림이 없고, 로그인한 사용자의 칸이어도 게스트로 보일 때는(로그아웃 후 새 게스트) 효과·그림을 그리지 않는다.
- 디자인 복사(아직 없음): 같은 방 플레이어의 정보 팝업(4.11)에서 [디자인 복사]를 누르면 그 사람이 장착한 프로필(`profile_id`)을 따라 한다. 바탕색, 테두리 색, 테두리 두께를 내 새 프로필(성장형)로 복사해 장착하고, 픽셀 그림과 업로드 이미지는 복사하지 않는다(상대가 `PIXEL`·`IMAGE` 프로필이어도 색과 두께만 가져온다). 복사하는 순간의 값을 가져오므로 상대가 나중에 바꿔도 내 프로필은 변하지 않는다. 내 레벨이 11 미만이면 할 수 없고, 색 변경 제한을 따른다.
- 금지 그림·이미지: 성적·폭력·혐오 표현, 타인 얼굴 사진, 타인 저작물, 개인정보. 위반이면 관리자가 꾸미기를 초기화하고(그림을 지우고 기본 모습으로), 반복하면 그림 저장을 정지한다(13.10).
- 닉네임 글자색은 배경 밝기에 따라 흰색·검정을 고르고 외곽선을 둔다. 작은 아이콘에서는 말줄임표로 줄인다.

### 4.10 칭호
- 조건을 달성하면 자동 지급되고 알림이 온다. 한 번 받은 칭호는 잃지 않는다. 칭호는 나라마다 따로 받고, 그 나라의 수치로 판정한다.
- 그 나라에서 보유한 칭호 중 최대 1개를 활성화해 닉네임 아래에 표시한다. 새로 얻어도 자동 활성화하지 않는다. 변경은 5초에 1번.
- 칭호와 조건은 모두 `titles` 테이블의 데이터(DB 값)다. 운영 중에 코드 배포 없이 추가·수정할 수 있고(13.4), 아래 목록은 처음 넣는 예시다. 칭호 ID는 아래 순서대로 넣어 정해진다(번역 키, 8절).
- 칭호함에서 보유 칭호, 획득일, 아직 못 얻은 칭호의 조건과 진행률을 볼 수 있다.
- 구현: 내 정보 창의 [🏅 칭호]로 칭호함을 연다. 받은 칭호에 [장착]·[해제](장착 중인 칭호는 받은 칭호 맨 위에 '장착 중' 배지와 함께, 장착은 따로 알리지 않고 해제만 "칭호를 해제했어요"), 못 받은 칭호에 조건 설명과 진행 막대(METRIC은 "37 / 100")를 보여 준다. METRIC 칭호는 수치가 바뀌는 요청(추가·잃기·만료·재합산, 댓글 점수)이 끝난 뒤 검사하고, RANK 칭호는 10초마다 리더보드를 본다. 새로 받으면 게임 화면 위 가운데에 새 칭호 알림 카드(🏅, 칭호 이름, 조건 설명, [장착하기], 닫기)가 뜨고 6초 뒤 저절로 사라진다(아래 줄이 줄어들며 남은 시간을 보여 준다). [장착하기]는 그 칭호를 바로 장착하고(`PUT /api/me/title`) "'○○' 칭호를 장착했어요"를 띄운다. 게임 메시지 `titleGranted`에 칭호 번호(`titleId`)가 함께 온다. 한꺼번에 여러 개 받으면 차례로 보여 준다. 장착한 칭호는 아레나의 닉네임 아래 노란 작은 글씨로 모두에게 보이고, 다른 플레이어 정보 팝업에도 나온다.

조건 쓰는 법: `titles.condition_type`과 `condition_params`(JSON)

| condition_type | condition_params | 뜻 | 판정 시점 |
|---|---|---|---|
| METRIC | `{"metric": "total_plus_count", "gte": 100}` | 플레이어 수치가 기준값 이상 | 그 값이 바뀔 때 |
| RANK | `{"metric": "current_score", "within": 10}` | 그 나라 리더보드(접속 중인 사람끼리의 순위, 4.14)에서 N위 안. 접속 중인 사람이 `rank_title_min_players`(기본 11명) 미만이면 순위와 관계없이 주지 않는다(혼자 있어도 1위가 되는 것을 막음) | 리더보드 갱신 |

- `metric`으로 쓸 수 있는 값은 `players`의 `total_plus_count`(누적 `+` 횟수), `level`(레벨, `players.level_id`가 가리키는 `levels`의 레벨), `hold_count`(지금 가진 키워드 수), `current_score`(현재 유행도), `comment_score`(댓글 점수), `search_count`(누적 검색 횟수), `steal_count`(다른 플레이어에게서 키워드를 빼앗은 횟수, 4.3), `bot_win_count`(봇을 이겨 보상을 받은 횟수, 4.21), `orb_count`(? 구슬을 먹은 횟수, 꽝 포함, 4.20), `lose_count`(충돌로 키워드를 잃은 횟수), `active_days`(플레이한 날의 수: 플레이어를 만든 날과 키워드를 얻은 날, 그 나라 시간대로 서로 다른 날, 추가·구슬·봇·빼앗기 모두 포함.`last_played_at`과 날짜가 다를 때 하루를 더 센다)다. 새 지표가 필요하면 `players`에 컬럼을 추가하고 `metric` 이름만 늘린다.
- 현재 유행도에는 EXP 점수 100이 들어 있어서 "현재 유행도 100"은 키워드 없이도 달성된다. 그래서 점수 조건은 500부터 시작한다.

### 4.11 다른 플레이어 정보 팝업
- PC는 다른 원을 우클릭, 모바일은 [🔍]을 누른 뒤 원을 탭하면 열린다(4.2): 아이콘·닉네임(관리자 배지)·활성 칭호, 현재 유행도·레벨·댓글 점수, 최근 7일 점수 그래프, 그 사람의 보관함 중 점수 상위 3개(이름, 상태 배지).
- 키워드 이름과 상태만 공개한다. 점수·시각은 숨긴다. 숨기기 설정은 없고 공개 범위를 개인정보 처리방침에 적는다.
- 키워드 이름을 누르면 키워드 상세 카드(4.12)가 열려 바로 `+`할 수 있다.
- [디자인 복사]: 그 사람의 꾸미기를 내 꾸미기로 가져온다(4.9). 11레벨 전에는 비활성으로 두고 "11레벨부터 쓸 수 있어요"를 보여 준다.
- 바깥 클릭·ESC·닫기로 닫는다. 게임은 멈추지 않는다. 모바일은 하단 시트.
- 구현: 세션 엔티티 번호로 `GET /api/room/players/{번호}`(정보)와 `.../score-history?range=7d`(7일 추이, 4.15)를 부른다. 나도 그 방에 접속해 있고 그 번호가 지금 방에 있어야 하며, 아니면 404 `PLAYER_NOT_IN_ROOM`. 유행도·레벨·닉네임은 방의 실시간 값, 상위 3개는 만료 전·금지 아닌 키워드를 트렌드 값 높은 순으로 고른다. 키워드를 누르면 정보 팝업을 닫고 키워드 상세 창(4.12)을 연다.
- [🚩 신고]: 제목 옆 버튼으로 그 플레이어를 신고한다(사유 선택, 같은 사람은 한 번만, 봇은 없음, 13.5).
- 아직 없는 것: [디자인 복사].

### 4.12 키워드 상세 카드와 댓글
키워드 이름이 보이는 모든 곳(검색 결과, 보관함, 정보 팝업, 채팅 `#키워드`)에서 같은 카드가 열린다. 뜻과 유행 이유는 맨 위의 AI 한 줄 설명과 사용자 댓글로 전달한다.

- 지금은 보관함의 항목과 검색 결과 카드의 키워드 이름을 누르면 게임 위에 창으로 열린다(게임은 멈추지 않는다). 채팅의 `#키워드`는 검색창에 넣어 검색한다(4.13).
- 창 구성: 키워드 이름과 그 옆 [💬 공유], 상태 배지와 트렌드 값(크게), [추가](보유 중이면 [보유중]과 남은 시간), 가진 사람 수·누적 `+` 수·누적 검색 수, 활동 그래프, 댓글. 활동 그래프는 창이 열려 있는 동안 1분마다 다시 읽는다.
- [💬 공유]: 누르면 채팅에 `#키워드`를 바로 보낸다(4.13). 채팅 태그는 공백 없는 글자만 이어지므로 공백을 빼고 보낸다(`두바이 쫀득 쿠키` → `#두바이쫀득쿠키`, 검색은 공백을 무시해 같은 키워드가 나온다). 채팅을 꺼 두었으면 켠다. 채팅 빈도 제한(1초 1회)을 따르고, 누른 뒤 1.5초 동안 버튼이 [공유함]으로 바뀐다.

```
┌──────────────────────────────────────────┐
│ 양쯔깐루  🔥활성 트렌드 67            [ + ]  │
│ 👥 1,204명 · 누적 + 4,321 · 검색 12,030    │
│ [활동]  24시간 7일 30일 180일  ━검색 ━+    │
│ ─ 댓글 128 ─────────────────────────────  │
│ 🥇 망고·자몽에 요거트 올린 홍콩 디저트예요 (👍 41) │
│ 🥈 편의점에서 컵으로 나와서 뜬 듯 (👍 23)         │
│ 🥉 여름 신메뉴로 카페마다 나오는 중 (👍 12)       │
│ ─ 최신순 ───────────────────────────────  │
│ 유나 · 3분 전: 어제 먹어봤는데 생각보다 달아요     │
│            ‹ 1 2 3 … 7 ›                     │
│ [댓글 쓰기]                         [신고]     │
└──────────────────────────────────────────┘
```

댓글
- 작성은 로그인 사용자만(구글 로그인을 만들기 전까지는 게스트도 쓸 수 있게 열어 둔다), 댓글 작성 정지(13.5) 중이면 쓸 수 없다(403 `COMMENT_BANNED`), 200자까지(최소 글자 수 제한 없음, 빈 댓글만 안 됨, 줄바꿈 허용), 링크·전화번호 불가, 한도 없음. 글자 수를 입력창 아래에 보여 준다. 수정은 5분 이내, 삭제는 언제든(소프트 삭제). 대댓글은 2차.
- 투표: 게스트 포함 누구나 댓글당 1표(👍/👎), 자기 댓글과 삭제·탈퇴 댓글은 불가. 같은 버튼을 다시 누르면 취소, 반대 버튼은 변경. 추천·비추천 수는 모두 공개.
- 정렬: 추천 상위 3개(추천 1개 이상, 동점이면 먼저 쓴 것)를 🥇🥈🥉로 고정하고, 나머지는 최신순 20개씩 페이지로 보여 준다. 비추천은 순위에 영향이 없다. 접힘·숨김은 없다.
- 신고: 남의 댓글에 [신고]를 두고, 사유(욕설·비방 / 스팸·광고 / 개인정보 노출 / 음란·폭력 / 기타)를 골라 신고한다(13.5). 내 댓글은 신고할 수 없다.
- 표시: 삭제한 댓글은 "삭제된 댓글이에요", 탈퇴한 사용자의 댓글은 "탈퇴한 사용자의 댓글이에요". 본문은 DB에 그대로 두고 관리자만 볼 수 있다.
- 댓글 점수(`players.comment_score`): 댓글을 쓰면 +1, 삭제하면 −1, 내 댓글이 추천을 받으면 +1, 비추천을 받으면 −1이다. 0 아래로 내려가지 않는다(오차를 막고, 비추천으로 점수가 마이너스가 되어 기분이 나빠지지 않게 하려는 것이다). 투표가 바뀌거나 취소되면 반대로 되돌린다(추천 → 비추천은 −2). 댓글을 삭제해도 그 댓글이 이미 받은 추천·비추천 점수는 되돌리지 않는다(삭제는 −1만 한다). 0에서 막힌 뒤 그 비추천이 취소되면 실제보다 1 높아질 수 있지만 허용한다. 프로필과 칭호에만 쓰고 크기에는 반영하지 않는다. 내 댓글이 상위 3개에 들면 알림을 보낸다.
- 댓글이 없으면 "아직 댓글이 없어요"만 보여 준다. 댓글이 있으면 목록 아래에 "사용자가 쓴 의견이며 사실 확인은 되지 않았어요" 라벨을 단다.

AI 한 줄 설명
- 카드 맨 위(상태·점수보다 위)에 "제미나이 로고(그라데이션 반짝이 별) + AI 한 줄 설명" 칸을 따로 둔다. 유행어·신조어·상품이면 어떤 뜻인지, 뉴스·이슈면 어떤 내용이 이슈인지를 한 문장으로 보여 준다(80자 안팎, 최대 200자). 설명이 아직 없으면 칸을 보여 주지 않는다. 키워드는 그 나라의 기본 언어별로 묶어 만들고, GLOBAL 키워드는 영어로 쓴다(10.4).
- 설명은 키워드마다 한 번 만들어 DB에 저장하고(`keyword_ai_comments`, 키워드의 `ai_comment_id`가 가리킴) 모든 사용자에게 같은 글을 보여 준다. 카드를 열 때마다 AI를 부르지 않는다. 만드는 시점은 키워드가 처음 🔥활성이 된 때(구글 목록, 관리자 추가, 외부 확인, 가진 사람 3명 모두 같다)이고, 실제로는 1분마다 도는 잡이 설명 없는 활성 키워드를 한도 안에서 만든다(10.4).
- 설명이 맞지 않으면 칸의 [설명이 이상해요]로 갱신을 요청한다. 한 사람이 한 키워드에 요청 하나만 둘 수 있고(다시 누르면 [갱신 요청함]), 요청은 사용자에게 바로 반영되지 않고 관리자 화면 [AI 설명] 탭에 접수된다(13.12). 관리자가 AI에게 다시 받거나 직접 고치면 새 설명이 모두에게 보인다.
- 라벨: AI가 만든 글이라 틀릴 수 있다. 모른다고 하면(`UNKNOWN`) 설명을 만들지 않는다. 비방·루머·사생활·선정적 표현은 쓰지 않도록 요청문에 정해 두고, 링크·너무 긴 글은 버린다.

활동 그래프
- 카드 가운데에 활동 그래프와 범위 선택 [24시간 | 7일 | 30일 | 180일]을 둔다(기본 24시간). 값은 `keyword_log_24h`(24시간)와 `keyword_log_dailies`(7일 이상)의 증분(9.9)이다. 24시간은 시간 단위, 7일·30일·180일은 하루 단위(나라 현지 날짜 기준) 점으로 그린다.
- 선: 검색 수, `+` 수. [가진 사람] 토글을 켜면 가진 사람 수를 오른쪽 축의 얇은 점선으로 겹쳐 보여 준다(기본 꺼짐). 카드 상단에 누적 `+` 수와 누적 검색 수도 보여 준다(`keywords.total_plus_count`, `search_count`).
- 느낌: 부드러운 곡선, 선 아래 옅은 그라데이션 면, 처음 열 때 왼쪽에서 오른쪽으로 그려지는 효과(`prefers-reduced-motion`이면 생략), 마우스·터치를 올리면 세로 안내선과 그 시간의 값 말풍선, 가장 높은 시간에 점과 "최고" 표시. 이번 시간은 집계 중이라 점선으로 그리고 끝점이 깜빡인다.
- 색만으로 구분하지 않게 선 모양(실선/파선)도 다르게 한다. 그래프 아래에 요약 문장("최근 24시간 검색 37회, `+` 12회, 오후 3시에 가장 많았어요")을 둔다. 시간은 선택한 나라의 시간대로 보여 준다.
- 기록이 없으면 "아직 기록이 없어요"를 보여 준다. 키워드를 직접 연 사람에게만 보이고, 활동이 많은 키워드 목록이나 순위는 만들지 않는다(3.3).

### 4.13 채팅
- 나라 방 단위 전체 채팅. 게스트도 쓸 수 있다. 메시지 100자(한 줄, 연속 공백은 하나로), 1초에 1회. 너무 빨리 보내거나 링크·전화번호가 있으면 보낸 사람에게만 이유를 알린다.
- 아레나 왼쪽 아래(내 정보 줄 위)에 둔다. Enter를 누르면 입력창으로 가고, Esc를 누르면 나와서 다시 조작한다. 새로 들어오면 그 방의 최근 50개를 보여 준다(서버를 다시 켜면 비워진다).
- 탭 없이 방 전체 채팅 하나만 둔다. 말풍선은 보낸 사람 아이콘 위에 3초.
- 채팅 입력 줄 오른쪽 끝 [▾]로 접으면 마지막 한 줄과 입력창만 남고, [▴]로 다시 펼친다. 펼치면 항상 최신 메시지(맨 아래)가 보인다. 아레나 오른쪽 위 [💬 채팅] 버튼이나 C 키로 채팅을 끄면 채팅 창과 말풍선이 모두 사라지고 Enter도 입력창으로 가지 않는다. 끈 동안 온 메시지는 다시 켜면 보인다. 켜짐·접힘 상태는 그 브라우저에 기억한다(처음에는 켜짐·펼침).
- 채팅 정지(13.5) 중이면 보낼 수 없고 이유와 끝나는 때를 알린다.
- `#키워드`를 누르면 검색창에 들어가 바로 검색한다. 링크는 차단하고 욕설은 필터링한다. 신고와 차단(내 화면에서 숨김)을 둔다. 욕설 필터(차단어 목록)와 차단은 아직 없다.
- 신고: 남의 메시지에 마우스를 올리면(터치 화면은 항상) [신고]가 보이고, 사유를 골라 신고한다(13.5). 신고된 메시지는 30일이 지나도 지우지 않는다.
- 모든 메시지는 30일 보관하고 지운다(신고 처리 중인 메시지는 남김). 개인정보 처리방침에 적는다.

### 4.14 랭킹
- 나라별 사용자 랭킹(리더보드)은 지금 그 나라 방에 접속한 사람만 집계하고, 현재 유행도 순서로만 정한다. 접속하지 않은 사람은 점수가 높아도 나오지 않는다. TOP 10을 보여 준다.
- 값은 DB가 아니라 방 메모리의 실시간 점수(1초마다 갱신)다. 화면은 켜져 있는 동안 3초마다 다시 읽는다. 점수가 같으면 먼저 만든 플레이어가 위다.
- 게임 화면 오른쪽 위 모서리에 겹쳐 보여 주고, [리더보드] 버튼이나 L 키(leaderboard)로 켜고 끈다(3.2). 내 줄은 강조한다. 오른쪽 패널의 [랭킹] 탭은 없다. 게임 중에도 뒤가 보이도록 배경을 반투명하게 하고(글자에는 그림자), 마우스를 올리면 진해진다.
- 키워드 랭킹은 두지 않는다.

### 4.15 점수 추이
- 나라별 현재 유행도를 1시간 단위로 기록하되, 플레이어마다 나라 현지 00시~23시 24칸에 덮어써서 최근 24시간만 남기고(`player_score_24h`, 행을 지우지 않는다), 하루 단위 기록(그날 마지막 값)은 영구 보관한다(`player_score_dailies`). 점수가 바뀐 시간만 기록한다. 이 테이블들은 그래프용 로그이고, 실시간 점수는 `players.current_score`에 있다.
- 내 프로필 "점수 추이" 탭: 24시간(시간 단위) / 7일 / 30일 / 전체(하루 단위). 선 그래프에 칭호 획득 시점 표시, 요약 문장("7일 전 120점 → 현재 148점").
- 다른 사용자는 정보 팝업에서 최근 7일(하루 단위)만 본다.
- 기록: 매시 정각 잡이 키워드가 있는 플레이어 점수를 점검(9.4)한 뒤, 그 시간에 행이 바뀌었고 직전 기록과 점수가 다른 플레이어만 그 나라 현지 시 칸을 덮어쓰고 그날 행을 그 값으로 맞춘다. 조회할 때 기록이 없는 시간·날은 직전 값을 이어 그리고, 마지막 점은 지금 값(접속 중이면 방의 실시간 점수)이다.
- 구현: 내 정보 창의 [점수 추이]에서 24시간 / 7일 / 30일 / 전체를, 다른 플레이어 정보 팝업에서 최근 7일을 본다. 칭호 획득 시점 표시는 아직 없다.

### 4.16 공지사항
- 관리자만 작성·수정·삭제한다. 모든 나라 공통이고, 제목·본문에 영어 칸(`title_en`·`body_en`)을 따로 둘 수 있다. 영어 칸이 비어 있으면 한국어를 보여 주고, 요청의 `Accept-Language`(ko/en)로 고른다. 제목 1~50자, 본문 1~5000자(텍스트, URL 자동 링크). 상단 고정, 소프트 삭제, 수정 시 "수정됨" 표시.
- 팝업: 등록할 때 팝업 여부(기본 켬)와 기간(1~90일, 기본 7일)을 정한다. 게임 화면에 들어올 때 아직 안 본 팝업 공지를 한 창에 최대 10개 모아 좌우로 넘겨 보여 주고(고정 공지 먼저, 그다음 최신순), 띄우는 순간 모두 "봤음"으로 기록해 다시 띄우지 않는다. 맨 위 [확인]이나 ESC로 닫는다.
- 게임 중 새 공지는 팝업 없이 [공지] 버튼에 빨간 점만 켠다. 목록에서 7일 이내 공지에 NEW를 붙인다.
- 구현: 관리자 화면 [공지] 탭에서 쓰고 수정하고 삭제한다(13.4). 본문은 가이드와 같은 문법(문단, 목록, 굵게, 팁 상자)으로 보인다.
- 구현: `GET /api/notices`의 `popup`(팝업 기간 안)으로 판단한다. "봤음"은 서버가 아니라 그 브라우저(localStorage)에 띄운 공지 번호로 기록한다(다른 기기에서는 한 번 더 뜰 수 있다). 팝업 창은 "📢 새 소식" 제목, 공지 하나씩(고정·NEW 배지, 큰 제목, 날짜, 본문), 아래에 ‹ › 버튼·점·"1 / 3"과 [확인]. 방향키로도 넘긴다. 공지 목록 창은 공지마다 카드(고정은 노란 테두리, 펼치면 초록 테두리)이고 맨 위 하나가 펼쳐져 있다. 빨간 점은 목록을 열었을 때 본 가장 큰 공지 번호보다 새 공지가 있으면 켜지고(모바일은 ☰ 메뉴와 메뉴 안 [공지사항]), 목록을 열거나 팝업을 닫으면 꺼진다. 게임 중에는 5분마다 다시 읽어 점만 켠다.

### 4.17 게임 가이드
- 관리자가 카테고리와 글을 관리한다. 카테고리마다 FAQ형(아코디언) 또는 문서형을 고른다. 본문은 마크다운(허용 태그만), 이미지는 관리자가 올린 파일만, 한국어와 영어(카테고리 `name_en`, 글 `title_en`·`body_en`, 비어 있으면 한국어). 영어 시드(카테고리 7개, 글 38개)는 서버가 시작할 때 영어 칸이 비어 있는 것만 채운다(11.3). 영어 본문에서도 그림 토큰은 한국어 토큰(`[[조작]]`)을 그대로 쓰고, 화면은 영어 별칭(`[[controls]]`, `[[growth icons]]`, `[[level icons]]`, `[[start steps]]`, `[[keyword states]]`, `[[arena legend]]`)도 받는다.
- 초기 카테고리: 🚀 시작하기, ⚔️ 점수와 대결, 🔎 키워드, 🗺️ 아레나, 🐢 성장과 꾸미기(이상 문서형), ❓ 자주 묻는 질문, 👤 계정과 신고(이상 FAQ형). 글 31개는 지금 동작하는 규칙(대결과 빼앗기, 봇, 세이프존, ? 구슬, 보관함, 댓글, 칭호, 꾸미기, 이동 효과, 구글 로그인, 신고, 탈퇴·복구)을 설명한다.
- 시드는 카테고리·글 테이블이 비어 있을 때만 넣는다. 그 뒤 시드 글을 고칠 때는 관리자가 고치지 않은 글만 바꾼다(11.3).
- 가이드는 놀이 방법을 쉬운 말로 설명하고, 점수식·계수·기준값 같은 세부 수치는 쓰지 않는다. 아직 없는 기능은 "준비 중"으로 적는다. 기능이 바뀌면 가이드도 함께 고친다.
- 본문 문법: 문단, `## ` 소제목(문단 첫 줄), `- ` 목록, `1. ` 번호 목록, `**굵게**`, `` `M` ``(키 모양으로 보임), `> `로 시작하는 줄(💡 팁 상자), `http://`·`https://` 주소 자동 링크(새 탭). 공지도 같은 문법이다. HTML은 넣지 않고 화면이 문법만 그리므로 본문에 태그가 섞여도 글자로 보인다.
- 본문의 한 문단을 정해진 `[[이름]]` 하나로 쓰면 그 자리에 게임 그림이 들어간다: `[[성장 아이콘]]`(1~10레벨 거북이), `[[레벨 아이콘]]`(10~100레벨 아이콘 바탕 표, `levels` 값을 읽어 그림), `[[시작 3단계]]`(찾기 → 추가 → 커지기 카드), `[[조작]]`(WASD 키, 모바일 조이스틱, M·L·C 단축키), `[[키워드 상태]]`(🔥·💤·⛔ 배지), `[[아레나 표시]]`(두 가지 세이프존, 나, 봇, ? 구슬). 이름이 틀리면 글자 그대로 보인다.
- 화면: 넓은 화면은 왼쪽에 카테고리 목록, 오른쪽에 글. 좁은 화면(760px 이하)은 위에 가로로 넘기는 카테고리 칩. 맨 위 검색 칸은 모든 카테고리의 제목·본문에서 찾아 결과를 보여 주고, 누르면 그 글로 이동한다(FAQ는 펼친다). 문서형은 맨 위에 글 목차 칩(누르면 그 글로 스크롤)과 카드 모양 글, FAQ형은 Q 표시가 있는 펼침 목록이다. 아래에 이전·다음 카테고리 버튼.
- 가이드·칭호 설명 등 사용자에게 보이는 글은 `+` 대신 "추가"라고 쓴다(버튼 표기 [추가]와 맞춤).
- 아직 없는 것: 서버 검색 API(지금은 화면이 글을 모두 불러와 찾는다), 글마다 고유 주소(`/guide/{카테고리}/{id}`), 게임 곳곳의 [?] 버튼에서 그 글로 바로 연결.
- 관리: 관리자 화면 [가이드] 탭에서 카테고리와 글을 만들고 고치고 지우고 순서를 바꾼다(13.4).

### 4.18 나라와 언어

나라

| 코드 | 지역 | 기본 언어 | 오픈 | 데이터 소스 |
|---|---|---|---|---|
| KR | 한국 | 한국어 | 열림(MVP) | 구글 실시간 인기(`geo=KR`) |
| GLOBAL | 영어권 통합 | 영어 | 열림 | 구글 트렌드 실시간 인기(`geo=US`) |
| JP | 일본 | 일본어 | 3단계 | 미정(16.1) |
| IN | 인도 | 힌디어 | 3단계 | 미정(16.1) |
| CN | 중국 | 중국어(간체) | 열지 않음 | 없음 |

- 한 사용자의 한 나라 기록을 플레이어라고 부른다(`players`). 닉네임, EXP·레벨, 칭호, 꾸미기, 트렌드 수치는 모두 플레이어에 속한다.
- 나라끼리는 완전히 별개다. 방·채팅·키워드·트렌드 값·댓글·랭킹과 사용자의 나라별 수치(유행도, 댓글 점수, `+` 횟수, 보유 키워드 수, 보관함)과 닉네임, EXP·레벨, 아이콘 꾸미기, 칭호가 나뉜다. 합계 점수나 통합 랭킹은 없다.
- 계정 단위로 공유: 방문자 ID·구글 계정, UI 언어, 계정 금지, 이미지 업로드 정지, 탈퇴. 닉네임은 나라마다 따로 정하며, 새 나라에 처음 들어갈 때만 마지막 닉네임을 미리 채워 준다.
- 나라(화면에는 '서버'로 표시)는 메인 화면 아래의 작은 목록에서 KR / GLOBAL로 고른다(3.1). 나라가 곧 UI 언어다(KR=ko, GLOBAL=en). 처음에는 브라우저 언어가 한국어면 KR, 아니면 GLOBAL이고(IP 국가는 보지 않는다), 고른 값은 localStorage `trendist.country`에 남는다. 나라를 바꾸면 페이지를 새로 불러오고, 그 나라 플레이어로 `GET /api/me?country=`를 불러 마지막으로 플레이한 지역(`users.country_id`)을 고친다. 나라는 언제든 바꿀 수 있고, 떠난 나라의 보관함은 남은 시간 동안 계속 기여한다. 한 계정은 한 번에 한 방에만 접속한다.
- 그 지역의 기본 언어를 지원하기 전에는 지역을 열지 않는다. 지금 열린 곳은 KR과 GLOBAL이다.
- 시간대: 날짜 경계(하루 단위 기록)는 나라 현지 시각(KR `Asia/Seoul`, GLOBAL `UTC`, JP `Asia/Tokyo`, IN `Asia/Kolkata`). 저장은 UTC, 화면은 선택한 나라 시간대.

언어
- 순서: 한국어(MVP) → 영어(지원 중) → 일본어·중국어 간체·힌디어. 번체와 다른 인도 언어는 지원하지 않는다.
- 언어 결정: 나라가 곧 언어다. 나라 선택(메인 화면) → 처음에는 브라우저 언어(한국어면 KR, 아니면 GLOBAL). 서버에는 `Accept-Language: ko|en`(없으면 ko)으로 알린다. 관리자 화면은 항상 한국어다.
- 번역하는 것: UI 문구, 칭호 이름·설명, 가이드, 공지, 이동·테두리 효과 이름, 잠금 사유, 채팅 오류 메시지, 서버 오류 메시지(코드로 화면이 번역). 번역하지 않는 것: 키워드, 댓글, 채팅, 닉네임. 약관은 아직 한국어뿐이다. 사용자 글 자동 번역은 2차.
- DB의 글은 한국어 칸을 기본으로 하고 영어 칸(`name_en` 등, 비어 있을 수 있음)을 따로 둔다(11.2). 서버는 `Accept-Language`가 en이면 같은 응답 필드에 영어 값을 넣고, 비어 있으면 한국어로 대체한다.
- 키워드 정규화(`keywords.normalized`, 같은 단어 판정용 비교 키): 공통 규칙은 NFKC → 소문자 → 모든 공백 제거 순서다(`K POP`, `ｋｐｏｐ`, `kpop`은 같은 키워드, `두바이 쫀득 쿠키`와 `두바이쫀득쿠키`도 같은 키워드). 화면에는 처음 입력한 표기(`text`)를 그대로 보여 준다. 하이픈 제거, 일본어 가나 규칙, 중국어 번체→간체(OpenCC), 힌디어 데바나가리와 로마자 처리 같은 언어별 규칙은 해당 나라를 열 때 추가한다. 한국어(KR)는 공통 규칙만 쓴다. 같은 함수를 검색, `+`, 외부 수집(10.2), 차단어 검사(4.6)에 쓴다.

### 4.19 트렌드 상자
아레나 곳곳에 잠깐 나타나는 상자를 열면, 지금 잘 나가는 키워드 하나를 나만 잠깐 볼 수 있다. 급상승 키워드를 모두에게 보여 주지 않는 원칙(3.3) 안에서, 직접 움직여 찾아간 사람에게만 주는 힌트다.

- 등장: 방마다 일정 간격(기본 5분)으로 무작위 위치에 생긴다. 한 상자는 일정 시간(기본 3분) 뒤 사라진다. 방에 동시에 최대 3개까지 있다. 벽 근처와 다른 상자 바로 옆에는 만들지 않는다.
- 키워드: 상자가 생길 때 서버가 그 나라에서 반영 소스가 외부인 🔥활성 키워드 중 트렌드 값이 기준 이상인 것 하나를 무작위로 정한다. 금지 키워드는 빼고, 최근 상자에 나온 키워드는 되도록 피한다. 같은 상자를 연 사람은 모두 같은 키워드를 본다. 후보가 없으면 상자를 만들지 않는다.
- 열기: 상자를 클릭한다. 내 아이콘이 상자 근처(기본 150px 이내)에 있어야 열린다. 멀면 "가까이 가야 열 수 있어요"를 보여 준다.
- 공개: 연 사람에게만 그 키워드의 카드(4.12, `+` 버튼 포함)를 일정 시간(기본 60초) 보여 준다. 시간이 지나면 카드에서 키워드 이름이 가려진다. 그동안 `+`하면 일반 `+`와 같다.
- 한 사람은 상자 하나를 한 번만 연다. 상자는 열어도 사라지지 않고 시간이 다 될 때까지 남아 있어서, 아직 열지 않은 사람은 각자 찾아가 열어야 같은 키워드를 볼 수 있다.
- 다른 사람에게 보이는 것은 상자의 위치와 남은 시간뿐이다. 누가 열었는지, 어떤 키워드인지는 보내지 않는다. 연 사람이 채팅으로 알려 주는 것은 막지 않는다.
- 상자 모양: 바닥 위에 반짝이는 선물 상자 아이콘, 사라지기 30초 전부터 깜빡임. 내가 이미 연 상자는 열린 모양으로 바뀐다. 미니맵에도 표시한다.
- 수치(간격, 유지 시간, 동시 개수, 최소 트렌드 값, 거리, 공개 시간)는 관리자 설정이다(13.3).

### 4.20 ? 구슬
아레나에 `?`가 새겨진 금빛 구슬이 떠다닌다. 내 원으로 덮으면 먹고, 정해진 확률(기본 50%)로 그 나라의 🔥활성 키워드 중 완전히 무작위로 하나가 보관함에 들어가고, 나머지 50%는 내가 가진 키워드 하나를 무작위로 잃는다(가진 것이 없으면 꽝). 타이핑 없이(모바일에서도) 키워드를 얻는 방법이지만 잃을 위험도 있고, 움직여서 찾아가는 이유가 된다.

- 등장: 목표 개수는 지금 활동 영역의 넓이에 비례한다(1,000×1,000px마다 기본 2.2개, 상한 기본 300개). 활동 영역 6,000×6,000px이면 약 79개, 12,000×12,000px(가장 좁을 때)이면 약 317개이지만 상한 300개까지만 뜨고, 48,000×48,000px(1000명)이면 약 5,069개이지만 역시 300개가 상한이다. 일정 간격(기본 3초)마다 목표의 5%(최소 1개)씩 생겨서 맵 크기와 관계없이 빈 아레나가 약 1분 만에 다 찬다. 구슬은 활동 영역 안 무작위 위치에 생긴다. 다른 원 바로 위, 벽 근처, 세이프존(4.22) 위에는 만들지 않는다. 활동 영역이 좁아져 밖에 남은 구슬은 사라진다. 모두 같은 구슬을 본다.
- 먹기: 원이 구슬 중심을 덮으면(원 반지름 + 구슬 반지름의 절반 안) 먹는다. 크기와 관계없이 누구나 먹을 수 있고, 먹는 순간 모두의 화면에서 구슬이 먹은 원 가운데로 빨려 들어가며, 먹은 원이 한 번 부풀고 금빛 고리가 퍼진다.
- 보상: 먼저 확률(기본 50%)로 당첨인지 정한다. 당첨이 아니면 내가 가진 키워드(금지 제외, 🔥·💤 가리지 않음) 중 하나를 무작위로 잃는다. 잃으면 인원·트렌드 값·점수를 일반 삭제와 같이 고치고, 충돌로 잃은 횟수·통계(`lose_count`, 충돌 통계)에는 세지 않는다. 가진 키워드가 없으면 꽝이다. 당첨이면 서버가 그 나라의 🔥 키워드(금지 제외) 중 하나를 가중치 없이 완전 무작위로 고른다.
  - 보관함에 없는 키워드면 일반 `+`와 똑같이 보관함에 넣는다(24시간 유지, EXP +1, 가진 사람 수 +1, 점수 반영).
  - 이미 보관함에 있는 키워드가 나오면 그 키워드의 만료시간만 지금부터 다시 24시간으로 갱신한다(점수·EXP·가진 사람 수 그대로, 사람에게서 빼앗을 때(4.3)와 같게).
  - 🔥 키워드가 하나도 없으면 빈 구슬이다.
- 결과 카드: 먹은 사람에게만 화면 위쪽에 3초 동안 보여 준다. 잃으면 "💨 키워드를 잃었어요", 키워드 이름, 상태 배지, 줄어든 유행도를 흐리게 보여 주고 보관함 목록을 새로 고친다. 잃을 것도 없으면 "꽝!"(살짝 흔들림)과 "잃을 키워드도 없어요"를 보여 준다. 새로 얻으면 "✨ 새 키워드를 얻었어요!", 키워드 이름, 상태 배지, 트렌드 값·가진 사람 수, 늘어난 유행도. 이미 가진 키워드면 "키워드를 갱신하였어요"와 이름을 흐리게 보여 주고, 보관함 목록의 남은 시간도 바로 새로 고친다. 다른 사람에게는 어떤 키워드가 나왔는지 보내지 않는다.
- 3.3과의 관계: 무엇이 나올지 고를 수 없고 먹은 사람에게만 하나를 보여 주므로, 급상승 목록을 보여 주지 않는 원칙의 예외로 둔다(트렌드 상자와 같은 이유).
- 미니맵에 작은 금색 점으로 보인다.
- **! 구슬**(4.25): 불꽃인 사람에게 키워드를 모두 잃은 사람 둘레에 떨어지는 붉은 구슬이다. `?`가 아니라 `!`이고 붉은 빛과 몸통이라 ? 구슬(금색)과 구별된다(미니맵에도 붉은 점). 먹는 규칙은 ? 구슬과 같지만 **꽝도 잃기도 없이 항상 🔥 키워드 하나를 얻는다**(`openPrizeOrb`). 가능하면 내 보관함에 없는 🔥 키워드에서 고르고, 다 가졌으면 아무거나(이미 가진 것이면 만료시간 갱신). 🔥가 하나도 없으면 빈 구슬이다. 주인이 없어서 누구나(봇 포함, 봇은 점수 하나 추가) 먹을 수 있고, 먹히지 않으면 90초 뒤 사라진다. 방 전체 상한 300개. ? 구슬의 목표 개수·생성에는 세지 않고 봇이 일부러 찾아가지도 않는다. 먹으면 구슬을 먹은 횟수(`orb_count`)에 센다.
- 수치(밀도, 상한, 생성 간격, 간격마다 생기는 비율, 🔥 키워드가 나올 확률)는 관리자 설정이다(13.3, `orb_density`, `orb_max`, `orb_spawn_seconds`, `orb_spawn_percent`, `orb_active_percent`). `orb_density`나 `orb_max`를 0으로 하면 끈다.

### 4.21 NPC 봇
사람이 적을 때 아레나가 비어 보이지 않고, 쫓고 피하고 구슬을 다투는 재미를 바로 느끼게 하려고 봇을 둔다.

- 인원: 방에 사람이 있으면 사람 + 봇이 기본 10명이 되도록 1초에 하나씩 채우고, 사람이 들어오면 하나씩 뺀다. 사람이 10명 이상이면 봇은 없다. 사람이 없으면 봇도 없다.
- 정직하게: 닉네임은 모두 **Bot**이고 원 바탕색이 빨간색이다(미니맵에서도 빨간 점). "현재 접속 N명"과 리더보드·정보 팝업 API·방 정원(1000명)에서는 빼고, 화면 위에 "봇 M"으로 따로 보여 준다. 채팅은 하지 않는다.
- 점수·레벨은 사람과 같은 기준이다: 봇은 방 메모리에 EXP와 "가진 키워드 점수" 몇 개(실제 키워드가 아니라 점수만, 하나에 20~50)를 가진다. 유행도 = min(EXP, 100) + 키워드 점수 합, 레벨 = 레벨표(`levels`)로 EXP에서 정한다. 그래서 크기와 성장 아이콘이 사람처럼 맞는다. 가진 키워드 수는 EXP(추가한 횟수)보다 많을 수 없다. DB에 저장하지 않고, 실제 키워드의 가진 사람 수·트렌드 값·랭킹에는 영향이 없다.
- 상한: 봇의 유행도는 그 방에 접속 중인 사람들 유행도의 평균(× `bot_cap_ratio`, 기본 1)을 넘지 않는다. 봇은 평균에 넣지 않는다. 평균이 작아지면 상한을 넘은 봇은 1초에 키워드 하나씩 내려놓고, EXP만으로도 넘으면 빠지고 새 봇으로 바뀐다(사람 평균이 0이면 봇도 0점 크기다).
- 변화: 15~45초마다 스스로 키워드를 하나 추가하거나(EXP +1, 상한 안에서만) 오래된 키워드가 사라진다(사람의 24시간 삭제처럼).
- 충돌: 사람과 같은 규칙(4.3)이다. 사람이 봇에게 지면 진짜 키워드를 하나 잃는다("Bot와 부딪혀 …"). 봇이 지면 가진 키워드 점수 하나를 잃고(없으면 잃을 것도 없고 보상도 없다), 이긴 사람은 보상으로 그 나라 🔥 키워드 중 하나를 무작위로 얻는다. 없던 키워드면 일반 추가와 같고(24시간 유지, EXP +1, 가진 사람 수 +1, 점수 반영), 이미 가진 키워드면 사람에게서 빼앗을 때(4.3)처럼 남은 시간만 지금부터 다시 24시간으로 늘린다(점수·EXP 그대로, "Bot을 이겨 '…' 키워드를 갱신하였어요!"). 구슬과 달리 꽝이 없고, 🔥 키워드가 하나도 없으면 "Bot을 이겼어요!"만 보여 준다. 보호 시간도 사람과 같다.
- ? 구슬: 봇도 먹을 수 있다. 사람과 같은 확률(기본 50%)로 당첨되면 사람처럼 "추가"한다(EXP +1, 키워드 점수 하나, 상한 안에서만). 나머지는 가진 키워드 점수 하나를 잃는다(없으면 꽝). 구슬은 사라진다.
- 움직임(서버, 최대 속도 같음): 봇마다 반응 속도(0.25~0.7초)가 달라 그 간격으로 다시 판단한다.
  - 도망: 나를 이길 원이 가까우면 반대쪽으로 도망치되, 벽에 몰리지 않게 안쪽으로 꺾고 좌우로 흔든다.
  - 추격: 내가 이길 원이 보이면 그 원이 갈 곳을 조금 앞질러 쫓는다. 4~7초 안에 못 잡으면 포기하고 5~10초 동안 쫓지 않는다(끝없이 따라오지 않게).
  - 구슬: 다른 봇이 노리지 않는 가까운 구슬로 간다(한 구슬에 몰리지 않게).
  - 배회: 진행 방향을 조금씩 틀어 곡선으로 돌아다니고, 벽 가까이면 가운데로 돌아서며, 가끔 0.6~2초 멈춘다.
  - 성격 셋(겁쟁이·사냥꾼·구슬 수집가)은 도망·추격·구슬을 알아채는 거리가 다르다.
- 정보 팝업(PC 우클릭, 모바일 [🔍] 뒤 탭)은 봇이면 서버에 묻지 않고 이름·BOT·현재 유행도·레벨만 보여 준다.
- 최소 인원: 사람이 `bot_players` 이상이어도 봇은 `bot_min_players`(기본 1)명 남는다. 봇이 하나도 없으면 봇 이기기(보상·칭호)를 할 수 없기 때문이다. 사람이 없으면 봇도 없다.
- 수치는 관리자 설정이다(13.3, `bot_players`, `bot_min_players`, `bot_cap_ratio`, `bot_step_min`, `bot_step_max`). 봇을 끄려면 `bot_players`와 `bot_min_players`를 모두 0으로 한다.

### 4.22 세이프존
부딪힘(튕김·키워드 잃기)이 없는 안전한 칸이다. 쉬어 가거나 처음 온 사람이 규칙을 익히는 곳이다.

- 가운데 고정 존: 맵 한가운데의 정사각형, 절대 사라지지 않는다. 파란색(칸 `rgba(79,140,255,0.16)`, 테두리 `#4f8cff`). 한 변은 활동 영역 한 변의 9%(최소 1,800px)라서 인원이 늘어 맵이 넓어지면 같이 커진다.
- 무작위 존: 활동 영역 곳곳에 작은 정사각형이 무작위로 생겨 5분 동안 있다가 사라진다. 연두색(칸 `rgba(166,224,74,0.14)`, 점선 테두리 `#a6e04a`)으로, 성장 캐릭터 바탕색(`#3fb68b`)과 구분된다. 한 변은 활동 영역 한 변의 2.5%(최소 1,200px), 개수는 넓이 10,000×10,000px마다 6개(상한 80개)다. 모자라면 1초에 하나씩 다른 존과 겹치지 않는 곳에 생긴다. 남은 시간을 칸 위에 보여 주고 사라지기 30초 전부터 깜빡인다. 활동 영역이 좁아져 밖으로 나간 존은 사라진다.
- 규칙: 원의 중심이 존 안에 있으면 그 원은 누구와도 부딪히지 않는다. 서로 겹쳐 있을 수 있고, 튕기지 않으며, 키워드도 잃지 않는다(밖의 원과 맞닿아도 마찬가지). 존이 사라지면 그 자리부터 평소 규칙이다.
- ? 구슬: 존이 생기거나(가운데 존이 커지거나) 하면 그 안에 있던 구슬은 사라지고, 존 위에는 구슬이 생기지 않는다(4.20).
- 처음 온 플레이어(아직 키워드를 한 번도 추가하지 않은 사람)는 가운데 고정 존 안에서 시작한다.
- 봇은 존 안의 원을 쫓지 않고, 자기가 존 안에 있으면 도망치지 않는다.
- 미니맵에도 가운데 존은 파란 칸, 무작위 존은 연두색 칸으로 보인다.
- 수치는 관리자 설정이다(13.3, `safe_center_ratio`, `safe_center_min`, `safe_zone_ratio`, `safe_zone_min`, `safe_zone_density`, `safe_zone_max`, `safe_zone_seconds`). `safe_zone_density`를 0으로 하면 무작위 존을 끈다.

### 4.23 이동 효과
움직일 때 원 뒤에 남는 꾸밈 효과다. 꾸미기 프로필(4.9) 칸마다 하나를 고르고(끌 수도 있다), 장착한 칸의 효과가 같은 방의 모두에게 보인다. 게임 규칙(충돌·속도)에는 영향이 없다.

| 코드 | 이름 | 모습 |
|---|---|---|
| `afterimage` | 잔상 | 지나온 자리에 내 원(바탕색)의 흐릿한 그림자가 남았다 작아지며 사라진다(약 0.4초) |
| `sparkle` | 별가루 | 네 갈래 작은 별이 깜빡이며 흩날린다 |
| `flame` | 불꽃 | 뒤쪽 가장자리에서 불티가 튀며 노랑 → 주황 → 빨강으로 식어 사라진다 |
| `bubble` | 물방울 | 물방울이 흔들리며 떠오르다 마지막에 살짝 커지며 톡 터진다 |
| `rainbow` | 무지개 | 지나간 길을 따라 색이 흐르는 띠, 꼬리로 갈수록 가늘고 옅다 |
| `footprint` | 발자국 | 좌우로 번갈아 작은 거북이 발자국이 찍혔다 옅어진다 |
| `petal` | 꽃잎 | 분홍 꽃잎이 돌며(팔랑) 흩날린다 |
| `heart` | 하트 | 하트가 콩닥(커졌다 작아짐) 뛰며 좌우로 흔들려 떠오른다 |
| `note` | 음표 | 알록달록 음표(♪·♫)가 흔들리며 떠오른다 |
| `bolt` | 번개 | 뒤쪽 가장자리에서 짧은 번개가 튀며 지직거린다(모양이 0.05초마다 바뀜) |
| `smoke` | 연기 | 뭉게구름 모양 연기가 퍼지며 옅어진다 |
| `snow` | 눈송이 | 여섯 갈래 눈송이가 천천히 돌며 흔들려 내려온다 |
| `pawprint` | 고양이·강아지 발바닥 | 둥근 바닥과 발가락 넷 모양 발자국이 좌우로 번갈아 찍혔다 옅어진다 |
| `birdprint` | 새 발자국 | 앞 발가락 셋과 뒤 발가락 하나(Y자)가 번갈아 찍힌다 |
| `bearprint` | 곰 발자국 | 크고 넓은 바닥과 발가락 다섯 모양이 번갈아 찍힌다 |
| `rabbitprint` | 토끼 발자국 | 길쭉한 뒷발 둘과 앞발 점 둘이 번갈아 찍힌다 |

- 입자는 움직인 거리마다 만든다. 멈춰 있으면 생기지 않는다. 간격은 원의 반지름에 비례하지만(작은 원과 같은 모양), 이동 속도는 크기와 관계없이 같아서 반지름 간격만으로는 큰 원에서 1초에 몇 개 나오지 않아 띄엄띄엄 끊겨 보인다. 그래서 움직이는 동안은 효과마다 정한 초당 최소 개수(불꽃·무지개 40, 별가루 24, 연기 16 등)가 나오도록 간격을 줄인다. 잔상은 겹치면 진해지므로 반지름 간격 그대로다.
- 크기는 원의 반지름에 비례하고(반지름 18px 미만은 18px로 본다), 흩날리는 속도는 입자 크기의 제곱근에 비례해 키운다. 큰 원의 입자가 제자리에 멈춘 것처럼 보이지 않게 하면서, 원 자신보다 훨씬 빨리 날아가지는 않게 하려는 것이다. 하트·음표·물방울·눈송이는 생길 때 잠깐 커지며 나타나고, 잔상은 옅게 시작해서 툭 튀어나오지 않는다.
- 효과는 원 아래에 그리고 속도는 크기와 관계없이 같아서, 큰 원은 자기 몸에 효과가 오래 가려진다. 그래서 입자·발자국·무지개 띠는 원의 뒤쪽 가장자리 바로 바깥에서 만들고, 수명을 반지름에 따라 늘린다(× (1 + 반지름/150), 최대 3배). 잔상은 지나온 중심에 남는 그림자라 더 늘린다(× (1 + 반지름/90), 최대 4.5배).
- 무지개 띠는 점마다 양옆 폭을 구해 조각으로 칠한다. 둥근 끝 선을 이어 그리면 굵은 띠(큰 원)의 이음매마다 반투명이 겹쳐 얼룩이 생기기 때문이다.
- 부담 제한: 원 하나당 입자 120개(무지개 띠 점 90개, 잔상 40개), 화면 전체 1,500개까지. 화면 근처의 원만 새 입자를 만든다. 한 프레임에 400px 넘게 움직이면(입장·보정) 순간 이동으로 보고 만들지 않는다. 봇은 효과가 없다. 효과는 모든 원 아래에 그린다.
- 자랑하기 카드(4.24)는 서버가 같은 규칙으로 멈춘 모습을 그린다(`TrailPainter`).
- 고르기: 꾸미기 프로필(4.9)의 [이동 효과]에서 고른다. 고르면 미리 보기(작은 아레나에서 원이 8자로 돌며 효과를 남긴다)에 바로 보이고, 프로필을 저장하면 그 칸에 들어간다. 장착한 칸이면 접속 중인 방에 바로 반영된다.
- 효과는 꾸미기의 하나라 꾸미기 해금 레벨(기본 11)부터, 구글로 로그인한 사용자만 쓴다. 게스트는 모든 효과가 🔒 "Google로 로그인하면 쓸 수 있어요"이고, 서버도 403 `EFFECT_LOCKED`로 막는다. 게스트로 보이는 원에는 효과를 그리지 않는다.
- 효과 목록은 테두리 효과와 같은 `effects` 테이블이고, 종류는 효과 종류 테이블 `effect_types`(`TRAIL` 이동 효과 / `BORDER` 테두리 효과)를 가리킨다(`effect_type_id`). 그림은 프론트엔드 코드가 코드값으로 그리므로, 코드에 있는 효과만 시드가 넣는다(이름·조건·순서·사용 여부는 운영에서 고친다). 효과 설명은 두지 않는다. 고르기·잠금 확인은 두 종류가 같은 규칙(`EffectRules`)을 쓴다.
- 얻는 조건(`unlock_type`): 꾸미기 해금·로그인 위에 효과마다 더 붙인다. 지금은 모두 `FREE`(조건 없음). 붙일 수 있는 조건은 `LEVEL`(`unlock_value` 레벨 이상), `TITLE`(`unlock_value` 칭호를 가짐), `PURCHASE`(결제). LEVEL·TITLE은 서버가 이미 확인하고, 조건을 못 채운 효과는 🔒와 조건 안내만 보인다. PURCHASE는 결제 기능이 없어 "구매하면 쓸 수 있어요(준비 중)"로 잠긴다. 결제를 붙일 때는 보유 효과 테이블(`player_effects`)을 추가해 산 효과를 기록한다(이동·테두리 효과 공통).

### 4.24 자랑하기 카드
내 기록을 카드 한 장으로 만들어 메신저·SNS에 올리게 해서, 공유를 보고 들어오는 사람을 늘린다.

- 위치: 내 정보 → [📸 자랑하기 카드]. 카드 미리 보기 아래에 버튼 세 개를 둔다. [💬 카카오톡 공유](노란 주 버튼, 카드 공유 주소를 카카오톡으로), [⬇️ 이미지 저장], [🔗 링크 복사](카드 공유 주소를 바로 클립보드에 복사). 카카오 JavaScript 키가 없으면 첫 버튼은 [📤 카드 공유]가 되어 공유 시트(없으면 카드 주소 복사)를 쓴다.
- 공유 주소: 카드를 여는 순간 서버가 그 시점의 값을 저장하고 공유 전용 주소(`사이트 주소/share/{코드}`)를 만든다. 코드는 추측할 수 없는 무작위 10자다. 그 뒤 꾸미기·레벨·칭호·점수가 바뀌어도 이미 만든 주소의 카드는 공유한 때 모습 그대로다. 값이 모두 같은 카드를 다시 열면 새로 만들지 않고 같은 주소를 쓴다.
- 이미지는 서버가 그린다: 저장한 값으로 요청 때 1080×1350(인스타 피드 4:5) PNG를 그리고 메모리에 캐시한다. 이미지 파일은 저장하지 않는다(값만 한 행). 클라이언트가 이미지를 올리지 않으므로 다른 그림으로 바꿔 퍼뜨릴 수 없다. 같은 주소의 이미지는 바뀌지 않으므로 브라우저·메신저가 오래 캐시해도 된다. 그림 코드(거북이, 카드 배치)를 고치면 이미 만든 카드도 새 그림으로 보인다.
- 미리 보기와 저장은 서버가 그린 같은 이미지를 쓴다.
- 공유 페이지(`/share/{코드}`): 카드 이미지와 [플레이 하러 가기](`/share/{코드}/play`를 거쳐 `/?ref=share`로)만 있는 작은 페이지다. 메신저 미리 보기용 OG 태그(`og:image`는 그 카드 이미지)를 넣어서, 주소만 붙여도 카카오톡·디스코드·X 등에서 카드가 보인다. 크롤러는 JavaScript를 실행하지 않으므로 백엔드가 HTML을 바로 준다.
- 카카오톡 공유: [💬 카카오톡 공유]를 누르면 바로 카카오톡 공유 창이 열린다(휴대폰은 카카오톡 앱, PC는 카카오톡 공유 창). 보내는 것은 카드 공유 주소뿐이다. 카카오가 공유 주소의 OG 태그를 읽어 카드 이미지가 든 메시지를 만든다(스크랩). 이미지를 카카오 서버에 올리지 않는다. 카카오 서버가 접속할 수 없는 로컬 주소(localhost 등)에서는 미리보기 없이 링크만 든 글 메시지로 보낸다. 공유 주소를 카드를 열 때 미리 만들어 두는 이유는 누른 뒤에 만들면 PC 브라우저가 공유 창을 팝업으로 막기 때문이다. 카카오톡 공유 웹훅(보낸 횟수)은 쓰지 않는다.
- 들어가는 것: 로고와 "내 트렌드 성적표", 내 원(꾸민 색·테두리, 고른 이동 효과가 왼쪽 아래에서 따라오는 모습), 닉네임, 장착한 칭호와 레벨, 현재 유행도, 리더보드 순위(TOP 10 안일 때만, 3위 안은 금색), 최근 7일 유행도 그래프, 가진 🔥 키워드(트렌드 값 높은 순 3개), 누적 기록 4칸(누적 추가, 빼앗기, 봇 사냥, 활동한 날), 바닥에 "트랜드를 아는 자, 커진다."와 사이트 주소. 값은 서버가 그 순간의 DB·방 값으로 정하고, 클라이언트가 보낸 값은 쓰지 않는다. GLOBAL 플레이어의 카드는 영어로 그리고(카드 값 `CardData.lang`=`en`) 공유 페이지·OG 태그도 영어다. KR 카드는 그대로다.
- 💤 키워드는 넣지 않는다. 곧 뜰 키워드를 알려 주게 되기 때문이다(3.3).
- 게스트도 만들 수 있다. 공유 카드는 영구 보관하고, 공유 페이지에는 카드의 닉네임·칭호·🔥 키워드가 그대로 공개된다(개인정보 처리방침에 적는다).
- 본 횟수: 공유 페이지를 연 수(조회)와 거기서 [플레이 하러 가기]를 누른 수(클릭)를 카드마다 센다. 같은 방문자(IP + 브라우저 정보의 해시, 메모리에만 두고 저장하지 않음)는 카드마다 하루(한국 시간) 1번만 센다. 메신저·검색 크롤러(카카오 스크랩, 디스코드, X, 페이스북 등)는 세지 않는다. 카카오톡 채팅방에서 미리보기만 보고 누르지 않은 것은 셀 수 없다(카카오가 이미지를 자기 서버에 캐시한다). 이미지 요청은 세지 않는다.
- 내 자랑하기 카드 창에는 내가 만든 모든 카드의 합계를 "내 카드를 지금까지 N명이 봤고 M명이 게임에 들어왔어요"로 보여 준다(들어온 사람이 아직 없으면 "내 카드를 지금까지 N명이 봤어요"). 0명이면 보여 주지 않는다. 관리자는 [공유] 탭에서 본다(13.8).
- 만들기는 사용자당 1분에 10번까지다(9.5). 공유 링크로 들어온 사람이 실제로 시작했는지(가입 전환)는 아직 세지 않는다.

### 4.25 연속 빼앗기와 콤보 불꽃
부딪혀서 키워드를 연속으로 빼앗으면 콤보가 쌓이고, 일정 수(기본 5)에 닿으면 원 둘레가 불꽃으로 타올라 잃기 전까지 유지된다. "이 사람은 지금 연속으로 이기는 중"을 한눈에 강조해서, 불타는 사람을 쫓아 불을 끄는 목표를 만든다.

- 콤보: 싸움(4.3)에서 이겨 키워드를 실제로 빼앗으면 +1. 봇을 이겨 키워드를 얻은 것도 센다(설정 `combo_bot_counts`, 기본 1). 상대가 잃을 키워드가 없어 아무것도 오가지 않으면 세지 않는다.
- 끊김: 한 번이라도 싸움에서 키워드를 잃으면(사람·봇 모두) 콤보가 바로 0이 되고 불꽃도 꺼진다. 24시간 삭제나 구슬과는 관계없다.
- 불꽃: 콤보가 `combo_flame_at`(기본 5) 이상인 동안 원 둘레에 불꽃 혀가 빈틈없이 둘러싸 천천히 돌며 일렁인다(바깥 주황 → 안쪽 노랑, 둘레에 옅은 열기). 콤보가 더 쌓여도 모양은 같다. 원보다 먼저 그려 둘레 바깥으로만 보이고, 크기는 반지름에 비례한다. 점수·크기·충돌에는 영향이 없다(보는 재미와 자랑).
- 보이기
  - 내 화면: 오른쪽 위 리더보드 아래 콤보 카드 "⚔️ 3 Combo", 불꽃이 붙으면 "🔥 5 Combo"(불빛 테두리).
  - 원 위로 떠오르는 글자("+12" 같은 점수 글자)와 겹쳐 보기 어려워서, 콤보는 원 위에 떠오르는 글자로 띄우지 않고 닉네임 아래에도 쓰지 않는다. 다른 사람의 콤보는 불꽃으로만 보인다.
  - 불꽃을 얻었다는 안내 글은 누구에게도 띄우지 않는다. 불꽃은 그 원의 둘레로, 내 콤보는 콤보 카드로만 보인다.
  - 꺼질 때: 잃은 사람에게만 "💨 ○○에게 져서 불꽃이 꺼졌어요". 불꽃을 끈 사람에게는 안내를 띄우지 않는다.
- 불꽃의 힘: 불꽃인 사람(콤보 ≥ `combo_flame_at`, 봇 제외)이 **불꽃 없는 사람**과 부딪히면(세이프존·보호 시간 규칙은 4.3·4.22 그대로) 유행도와 상관없이 불꽃 쪽이 이기고, 상대는 가진 키워드(금지 제외, 🔥·💤 무관)를 **모두** 잃는다. 이긴 쪽은 키워드를 빼앗지 않지만 콤보는 +1이다. 잃은 쪽은 콤보가 0이 되고 3초 무적이다. 상대가 키워드가 없으면 아무 일도 없다. **둘 다 불꽃이면** 평소(4.3)처럼 유행도가 낮은 쪽이 하나 잃고 이긴 쪽이 빼앗는다(진 쪽 불꽃은 꺼진다). **봇**과의 싸움은 불꽃이어도 평소 규칙 그대로다(불꽃인 사람이 봇에게 져도 하나 잃고 콤보가 끊긴다).
- 떨어지는 구슬: 모두 잃으면 잃은 키워드 중 **🔥활성이던 개수** × `combo_wipe_orb_percent`(기본 50%, 올림, 활성이 하나라도 있었으면 최소 1개, 💤만 잃었으면 0개)만큼 **! 구슬**이 잃은 사람 둘레(원 가장자리 바깥, 활동 영역 안, 세이프존 밖)에 흩어진다. ! 구슬은 4.20을 따른다. 잃은 사람에게는 "불꽃에 키워드 N개를 모두 잃었어요!", 이긴 사람에게는 "🔥 불꽃으로 ○○의 키워드 N개를 모두 날려 버렸어요!"를 알린다.
- 서버: 방 메모리(`Room.Member.combo`)에서만 센다. DB에 저장하지 않는다. 키워드가 실제로 오간 뒤(빼앗기·잃기 처리가 끝난 뒤) 방이 콤보를 고치고 `combo` 메시지(`event`: up / start(불꽃이 붙음) / reset / broken(불꽃이 꺼짐), `flameAt`)를 방 전체에 보낸다. 들어오는 사람은 명단(`roster`)의 `combo`와 `flameAt`으로 받는다. 나간 뒤 1분 안에 다시 들어오면(4.2) 콤보를 이어 가고, 서버를 다시 켜면 사라진다.
- 수치는 관리자 설정이다(13.3, `combo_flame_at`, `combo_bot_counts`, `combo_wipe_orb_percent`).

### 4.26 이모트
채팅 없이 원 위에 이모지를 잠깐 띄운다. 모바일에서도 쉽게 반응을 주고받게 한다.

- 8가지: 👋 안녕, 😂 웃음, 😎 여유, 😭 울음, 😡 화남, 👍 좋아, ❤️ 하트, 🔥 불타오름. 코드(`wave`, `laugh`, `cool`, `cry`, `angry`, `thumbs`, `heart`, `fire`)만 주고받고, 서버는 정해진 코드만 받는다.
- 보내기: 아레나 오른쪽 아래 [😀]를 누르거나 PC에서 E 키로 이모트 창을 열고, 눌러서 또는 숫자 1~8로 고른다. 하나를 보내면 창이 접힌다(창이 닫혀 있을 때 숫자 키는 이모트로 쓰지 않는다). 게스트도 쓸 수 있다. 2초에 한 번꼴(잠깐 몰려도 3번까지, 게임 WebSocket 토큰 버킷). 넘으면 조용히 버린다.
- 보이기: 같은 방 모두의 화면에서 그 원 위(채팅 말풍선이 있으면 그 위)에 큰 이모지가 튀어 오르듯 나타나 2.5초 뒤 사라진다. 기록은 남기지 않는다.

### 4.27 대시
짧게 빨라져서 쫓기던 상황을 벗어나거나 상대를 따라잡는 기술이다. 크기·점수와 관계없이 누구나 같은 규칙으로 쓴다.

- 효과: 쓰면 **기본 3초** 동안 최대 속도가 평소의 **기본 2배**가 된다(`dash_seconds`, `dash_speed_multiplier`). 튕김(4.3)의 거리와 가속·감속 곡선은 그대로이고 최대 속도만 배수가 된다.
- 쿨타임: 쓴 때부터 **기본 30초**가 지나야 다시 쓴다(`dash_cooldown_seconds`, 대시 3초를 포함해 센다). 대시 시간보다 짧게 정해도 대시가 끝나기 전에는 다시 쓸 수 없다.
- 조건: 움직이려는 중일 때만 쓸 수 있다(방향 입력이나 이동 목표가 있을 때). 가만히 있을 때 눌러도 아무 일이 없고 쿨타임도 쓰지 않는다. 세이프존 안에서도 쓸 수 있다. 봇은 대시를 쓰지 않는다.
- 쓰는 법
  - PC: **스페이스바**. 길게 눌러도 한 번만 쓰고, 채팅 입력 중에는 무시한다.
  - 모바일: 한 손가락으로 **조이스틱(또는 터치 이동)을 쥔 채 다른 손가락으로 화면 어디든 탭**한다. 정해진 자리가 없어서 오른손·왼손 어느 쪽이든 쓴다. 다른 손가락이 UI 버튼 위를 누르면 그 버튼이 눌리고 대시는 아니다. 터치 기기에는 처음 한 번만 방법을 알려 주는 안내를 띄운다.
- 표시: 오른쪽 아래 이모트 버튼(😀) 바로 왼쪽에 ⚡ 표시가 있다(내 정보 줄에는 두지 않는다). 준비되면 "⚡ 대시", 쓰는 동안은 "⚡ 대시 N초"(노란색), 쿨타임에는 "⚡ N초"와 줄어드는 막대. 
- 강조 효과: 대시를 쓰면 **같은 방 모두의 화면**에서 그 원이 눈에 띈다(관전 포함, 대시가 켜진 3초 동안). 색은 하늘색·흰색이라 콤보 불꽃(주황, 4.25)과 구분된다.
  - 시작: 원 둘레로 퍼지며 사라지는 충격파 고리(0.5초)와 원 위로 튀어 오르는 ⚡(0.7초).
  - 대시 중: 원 둘레의 은은한 하늘색 빛과 가는 방향의 반대쪽(원 뒤)으로 갈수록 좁아지며 사라지는 하늘색 꼬리 빛(속도선은 없다). 꼬리 빛은 원 가까이가 가장 진하다. 나타나고 사라질 때 부드럽게 변한다.
  - 멀리서 줄여 봐도 보이게 둘레 빛·고리 두께의 최소값을 화면 픽셀로 잡는다. 모션 줄이기 설정과 관계없이 그리되 깜빡임은 없다(설정이 켜져 있으면 일렁임도 뺀다). 이름표·미니맵에는 표시하지 않는다(대시하는 위치를 멀리서 드러내지 않으려는 것).
- 서버: 클라이언트가 `dash`를 보내면 방이 쿨타임과 움직이는 중인지를 보고 시작한다(`Room.dash`). 시작하면 본인에게 `dash{ms, cooldownMs, mult}`를 보내고 방 전체(관전자 포함)에 `dashFx{e, ms}`를 보내 효과를 그리게 한다. 본인에게는 내 화면의 예측이 같은 속도로 가게 한다(보정이 생기지 않게). 거부된 요청은 아무 응답이 없다. 방 메모리에서만 세므로 DB에 저장하지 않고, 다시 접속하면 쿨타임이 없다.
- 수치는 관리자 설정이다(13.3, `dash_speed_multiplier` 1~5, `dash_seconds`, `dash_cooldown_seconds`). 1초마다 다시 읽어 다음 대시부터 반영된다.

중복 조사
- 영문·한글 웹 검색에서 "키워드 검색 + 트렌드 점수 + 크기 + 밀어내기 충돌"을 결합한 게임은 찾지 못했다. 가까운 사례는 밀어내기 파티게임 Bubble Brawl(itch.io)과 트렌드 모음 앱 정도다. 출시 전에 Poki, CrazyGames, itch.io, 앱스토어를 직접 확인한다.

이름
- Trendist = trend + -ist(트렌드를 쫓는 사람). 검토했던 후보: 급상승.io, Trendsetter, Riser, Trender, Hipster, Trendier, 유행왕, 핫범퍼.io, 트렌드 스모. Trendsetter·Hipster 같은 어휘는 칭호로 쓴다.
- 같은 이름의 Trendist.AI(trendist.ai), 'The Trendist' 뉴스레터가 있어 혼동 가능성이 있다.
