# Trendist 3부. 운영

> 문서 목록과 변경 이력은 [docs/README.md](README.md). 절 번호(1~17)는 네 문서에 걸쳐 이어지고, 코드 주석의 `(4.8)` 같은 번호가 이 번호다.

## 13. 관리자 기능
관리자 화면은 React, API는 `ROLE_ADMIN` 전용이다. 관리자가 직접 운영한다.

접근과 권한
- 관리자 화면은 게임과 따로 만든 페이지 `/admin/`이다(로컬 `http://localhost:8080/admin/`, 빌드 결과 `admin/index.html`이라 웹 서버가 폴더 주소로 연다). 관리자 계정이면 게임 도구 줄과 ☰ 메뉴에 [🛠 관리자]가 보여 새 탭으로 연다. 관리자가 아닌 사람의 화면에는 링크가 없고 검색 엔진에도 올리지 않는다(`noindex`).
- 게임에서 Google로 로그인한 계정의 갱신 토큰으로 들어온다. 서버는 `/api/admin/**`를 `users.role = ADMIN`인 계정만 받는다(JWT 확인 때 30초 캐시로 권한을 읽어 `ROLE_ADMIN`을 준다). 로그인하지 않았거나 권한이 없으면 "접근할 수 없는 페이지예요"만 보여 주고 이유·방법·계정 번호 같은 정보는 주지 않는다(`GET /api/me/admin`도 관리자인지만 돌려준다).
- 권한은 운영자가 DB에서 준다. 계정 번호는 그 사람의 닉네임으로 찾는다: `SELECT u.id FROM users u JOIN players p ON p.user_id = u.id WHERE p.nickname = '<닉네임>' AND u.oauth_id IS NOT NULL;` → `UPDATE users SET role = 'ADMIN' WHERE id = <계정 번호>;`(30초 안에 반영). 구글 로그인 계정에만 준다.
- 화면 탭: 대시보드(13.11, 처음 열리는 탭), 통계(13.9), 관전(13.13), 사용자(13.10), 키워드(13.1, 13.6), 키워드 추가(13.7), 신고(13.5), 공지(13.4), 가이드(13.4), 공유(13.8), 설정(13.3).

### 13.1 키워드 금지
- 금지·해제만 하고 금지한 사람·사유·이력은 남기지 않는다. 금지 시각만 `keywords.banned_at`에 둔다.
- 금지 효과는 4.7.
- 신고된 키워드는 검토 목록에 올라오고 관리자가 판단한다. 신고 수에 따른 자동 조치는 없다.

### 13.2 소스 가중치
- 소스별 가중치(0~2)를 바꾼다. 0으로 두면 그 소스를 쓰지 않는다. 변경 이력은 남기지 않는다(키워드 금지와 같은 방식, 13.1).
- 저장하면 그 소스를 반영 소스로 쓰는 키워드의 `trend_value`를 바로 다시 계산하고, 보유자의 점수는 접속 중이면 바로, 아니면 다음 재합산(최대 1분)에 반영된다. 외부 확인과 반영 소스 선택은 다음 목록 조회(5분마다)부터 새 가중치를 따른다.
- 크기가 바로 바뀌므로 저장 전에 영향받는 키워드·사용자 수를 보여 준다. 바꾼 직후 하루 동안(`data_sources.updated_at` 기준)은 💤 전환을 보류한다.
- 외부 API가 막히면 그 소스의 가중치를 0으로 한다(그 나라의 키워드는 외부 확인 없이 internal 점수로만 계산된다).

### 13.3 밸런스 설정

### 13.4 콘텐츠 관리
- 칭호: 이름·설명(한글)·아이콘·조건(`condition_type`·`condition_params`, 4.10)·순서·사용 여부를 추가·수정한다. 기준을 바꿔도 이미 준 칭호는 회수하지 않는다.
- 레벨: `levels`의 레벨별 누적 EXP를 보고 수정한다. 1레벨은 0이고, 1~100레벨이 빠짐없이 있어야 하며, 레벨이 오를수록 값이 커져야 한다(엄격 증가). 저장하면 모든 플레이어의 레벨을 다시 계산한다(배치, 저장 전에 레벨이 바뀌는 사용자 수를 보여 준다). 이미 장착한 꾸미기는 유지하고 변경만 새 레벨 기준으로 제한한다. 변경 이력은 남기지 않는다.
- 꾸미기: 프리셋 색 24색은 설정(코드)으로 관리하고 관리자 화면에서 바꾸지 않는다(2차).
- 공지·가이드 작성(4.16, 4.17), 금지 닉네임·차단어 등록.
- 구현(공지): 관리자 화면 [공지] 탭. 위에서 제목(1~50자)·본문(1~5000자)을 쓰고 글자 수를 보며, 오른쪽에 게임의 공지 창과 같은 모양으로 미리 본다(문단, `- ` 목록, `**굵게**`, `> ` 팁 상자). 📌 고정, 팝업 여부·기간(등록일부터 1~90일, 기본 7일)을 고른다. 아래 목록에서 [수정](위 칸에 채워 고침, 팝업 기간은 등록일 기준 그대로)과 [삭제](한 번 더 확인, 소프트 삭제)를 한다.
- 화면: 쓰기 카드는 제목 칸을 크고 굵게(1.2rem) 두고, 본문 옆 미리 보기는 사용자 공지 창과 같은 모양이다. 본문 아래에 문법 한 줄 안내. 📌 고정과 🔔 팝업은 설명이 붙은 토글 카드(켜면 초록 테두리)이고, 팝업을 켜면 "올린 날부터 [7]일 동안"이 나온다. 버튼은 [공지 올리기] / 수정 중이면 [수정]과 위쪽 [취소], 카드에 초록 테두리. 목록은 공지마다 카드(고정·🔔 팝업 중 ~까지/팝업 끝남·수정 중 배지, 큰 제목, 날짜, [본문 보기] 펼침, 오른쪽에 [수정]·[삭제])다.
- 본문 편집기(공지·가이드 공통): 글 칸 위에 서식 단추 줄 — **B** 굵게(Ctrl+B), **H** 소제목, • 목록, 1. 번호 목록, 💡 팁 상자, ⌨ 키 모양, 🔗 링크(Ctrl+K, 주소를 물어 넣음), 가이드는 🖼 그림 넣기(게임 그림 `[[이름]]`), ? 문법 도움말. 단추는 고른 글을 감싸거나 고른 줄 앞에 기호를 붙이고, 이미 붙어 있으면 뗀다. 단추로 바꾼 것도 Ctrl+Z로 되돌린다. 저장 형식은 본문 문법(글자) 그대로이고 옆 미리 보기가 사용자 화면과 같은 모양으로 바로 바뀐다. 위지윅(HTML 저장)은 쓰지 않는다: HTML을 저장하면 태그 걸러 내기(XSS)와 공지·가이드 화면을 모두 바꿔야 하고, 지금 문법이면 저장된 글을 그대로 안전하게 그릴 수 있다.
- 구현(가이드): 관리자 화면 [가이드] 탭. 왼쪽은 카테고리 목록(이름, 형식, 글 수, 숨김 배지, ▲▼ 순서), [+ 새 카테고리]. 오른쪽 위는 고른 카테고리 정보와 [카테고리 수정](이름 1~100자, 📄 문서형 / ❓ FAQ형, 👁 사용자에게 보이기)·[삭제](글이 없을 때만, 있으면 숨기기를 쓴다). 코드(영어 소문자·숫자·하이픈 2~50자)는 만들 때만 정하고 바꾸지 못한다(사용자 화면이 코드로 카테고리를 찾는다). 아래는 글 목록(▲▼ 순서, [수정], [삭제] 한 번 더 확인·소프트 삭제)과 [+ 새 글]. 글 편집은 제목(FAQ는 질문) 1~100자, 본문(FAQ는 답변) 1~20,000자, 미리 보기는 사용자 가이드 창과 같은 카드·FAQ 모양이다. 저장하지 않고 다른 글로 넘어가면 한 번 묻는다. 바뀐 글은 사용자 가이드 창을 다시 열면 바로 보인다(캐시 없음).
- 시드와의 관계: 시드는 카테고리·글 테이블이 비어 있을 때만 넣으므로, 관리자가 고치거나 지운 글을 시드가 바꾸거나 되살리지 않는다(11.3).

### 13.5 신고와 이미지 검열
- 신고 대상: 키워드, 댓글, 아이콘 이미지, 플레이어, 채팅(유형은 `report_types`). 신고는 신고한 플레이어가 기록되어 어느 나라에서 신고했는지 알 수 있고, 계정은 플레이어를 통해 찾는다(제재는 계정 단위, 아래 사용자 제재). 한 플레이어가 같은 대상을 한 번만 신고한다. 모든 신고는 관리자 검토로 처리하고 자동 조치는 없다. 신고하면 대상의 `report_count`를 1 올린다(댓글·채팅). 지금은 댓글·채팅·플레이어 신고를 받는다(`POST /api/reports`). 플레이어 신고는 다른 플레이어 정보 팝업(4.11)의 [🚩 신고]로 하고, 같은 방에 있을 때만 세션 엔티티 번호를 서버가 플레이어 번호로 바꿔 저장한다.
- 신고 탭의 "같은 대상 함께 처리"는 켜고 끄는 스위치로, 켜면 처리할 때 같은 대상에 들어온 다른 접수 신고도 같은 결과로 바꾼다.
- 관리자 검토(신고 탭): 처리 상태(접수 `RECEIVED` / 조치함 `RESOLVED` / 문제없음 `REJECTED`)로 걸러 최신순 30건씩 본다. 한 줄에 유형, 신고된 사람([사용자 보기 ›]로 사용자 탭 상세), 그 사람에게 지금 걸린 제재, 신고자, 같은 대상 신고 수, 사유, 신고된 글 원문(댓글은 키워드 이름도, 지운 댓글은 흐리게)을 보여 준다. "같은 대상의 접수 신고도 함께 처리"를 켜면 같은 대상의 아직 접수 상태인 신고도 같이 바뀐다.
- 신고에서 바로 조치: 접수 상태의 신고 아래 조치 칸에서 제재 종류(제재 없이 / 채팅 정지 / 댓글 작성 정지 / 그림 저장 정지 / 계정 금지), 기간(1·3·7·30일·영구), 사유(비우면 "신고 #번호(유형): 신고 사유")를 고르고, 댓글 신고면 "신고된 댓글 지우기"(소프트 삭제)도 고른 뒤 [제재하고 조치함]을 누른다. 한 번 더 확인하면 그 사람에게 제재를 걸고(사용자 탭과 같은 처리, 계정 금지면 내보냄) 신고를 조치함으로 바꾼다(`POST /api/admin/reports/{id}/act`). 문제가 없으면 [문제없음]. 유형별로 미리 골라 두는 값은 채팅 → 채팅 정지 1일, 댓글 → 댓글 작성 정지 1일 + 댓글 지우기, 플레이어 → 제재 없이. 처리한 신고는 [접수로 되돌리기]만 있고, 걸린 제재는 사용자 탭에서 푼다.
- 이미지 자동 검열
  - 경량 NSFW 모델(GantMan/nsfw_model 또는 Yahoo open_nsfw)을 ONNX로 돌려 높으면 거부, 애매하면 저장 후 검토 목록. 선정성만 보므로 나머지는 신고와 사용자 제재로 대응한다.
  - 모델을 쓸 수 없거나 실패하면 거부하지 않고 검토 목록에 올린다.
  - 위반 이미지의 지각 해시(pHash)로 다시 올리는 것을 막는 기능은 2차다(5.1).
- 사용자 제재: 관리자가 사용자 탭(13.10)이나 신고 탭에서 계정 금지, 그림·이미지 업로드 정지, 댓글 작성 정지, 채팅 정지를 걸 수 있다(종류는 `sanction_types`). 채팅 정지 중이면 채팅을 보낼 때 `chatError` `CHAT_BANNED`("채팅이 정지된 계정이에요(…까지)")를 받는다(15초 캐시라 걸고 나서 최대 15초 뒤 막힐 수 있지만 거는 순간 캐시를 비운다). 반복 위반이면 걸고, 걸 때마다 사유와 기간을 `sanctions`에 남긴다. 기간은 걸 때 관리자가 고르고(1·3·7·30일·영구) 만료 예정 시각(`expires_at`)에 넣는다. 영구 제재는 `9999-12-31 23:59:59`로 둔다. 만료 전에 관리자가 풀면 실제로 푼 시각(`released_at`)을 기록한다. 제재 중인지는 `released_at`이 없고 `expires_at`이 지금보다 뒤인지로 판단한다.
- 현재 상태는 빠르게 확인하려고 `users`에도 둔다: 계정 금지는 `banned_until`, 이미지 업로드 정지는 `upload_banned_until`. NULL이면 제재 없음, 지금보다 뒤 시각이면 제재 중이다. 만료는 시각 비교로 자동이라 따로 잡이 필요 없다. 제재를 걸거나 풀 때 `sanctions`와 `users`를 한 트랜잭션에서 같이 고친다. 댓글 작성 정지는 댓글을 쓸 때만 확인하므로 `sanctions`에서 직접 조회한다.
- 금지된 계정은 입장할 수 없고 접속 중이면 연결을 끊는다. 게스트는 쿠키를 지우면 새 방문자 ID를 받아 금지를 피할 수 있으므로, 로그인한 계정만 확실히 막을 수 있다.
- 삭제·탈퇴한 댓글 원문은 신고·법적 요청 대응 때만 열람한다.

### 13.6 트렌드 키워드 목록
관리자만 보는 조회 화면이다(`ROLE_ADMIN`). 일반 사용자에게는 보이지 않으므로 3.3의 비노출 원칙과 충돌하지 않는다. 나라를 고르면 그 나라 키워드를 보여 준다.

- 열: 키워드, 상태, 트렌드 값, 반영 소스, 가진 사람 수, 누적 `+` 수, 누적 검색 수, 최근 24시간 검색 수·`+` 수(`keyword_log_24h` 증분 합), 🔥가 된 날.
- 필터: 상태, 반영 소스, 키워드 검색어, "반영 소스가 internal(사람만으로 활성)"만 보기. 정렬: 트렌드 값 / 가진 사람 수 / 누적 `+` 수 / 최근 24시간 검색 수. 한 페이지 50개.
- 소스별 관심도 값은 저장하지 않으므로 보여 주지 않는다(10.2).
- 행을 열면 일반 카드와 같은 활동 그래프(4.12)를 보여 주고, 거기서 바로 금지·해제할 수 있다(13.1).
- 조회 전용이고 결과는 1분 캐시한다. 내보내기(CSV)는 2차다.
- 구현: 맨 위에 검색 칸, 그 아래에 상태(전체·🔥·💤·⛔)와 소스(전체·google·admin·internal) 칩이 있다. 칩은 여러 개를 고를 수 있고(눌러서 켜고 끔, 안 고르면 전체), 상태 칩에 개수를 보여 준다(소스·검색어는 적용, 상태는 빼고 센다). 상태가 전체이거나 여러 개이면 금지 키워드를 맨 위에 모은다(안내 문구는 띄우지 않는다)(금지하면 트렌드 값이 0이라 점수순으로는 마지막 쪽에 묻히기 때문이다).

### 13.7 관리자 키워드 추가
- 관리자가 키워드를 바로 🔥활성으로 넣는다. 반영 소스는 `admin`(가중치 1, `data_sources`)이라 관리자가 넣은 것을 구분할 수 있다.
- 넣은 때부터 `external_until` = 지금 + `external_hold_hours`(기본 168시간 = 7일). 구글 목록처럼 유지 기간형 소스로 다루고, 기간이 끝나면 1분 잡이 반영 소스를 `internal`로 내리고 가진 사람이 3명 미만이면 💤로 바꾼다(다시 확인해 줄 목록이 없으므로 연장하지 않는다).
- 이미 있는 키워드면 반영 소스를 `admin`으로 바꾸고 🔥로 만들며 지금부터 다시 7일이다. 금지된 키워드는 거절한다(먼저 해제). 등록 조건(4.6)은 사용자와 같다.
- 쉼표로 나눈 여러 키워드를 한 번에 넣을 수 있다: 입력 → [확인]으로 넣을 목록(공백·대소문자만 다른 중복 제거)을 보여 주고 → [추가]를 누르면 하나씩 넣으며 키워드마다 결과(새로 만듦 / 이미 있던 키워드를 admin으로 / 실패 이유)를 보여 준다.
- `admin` 가중치를 0으로 하면 쓰지 않는다(넣기를 거절).

### 13.8 공유 통계
자랑하기 카드(4.24)가 실제로 사람을 데려오는지 본다. 조회 전용이다.

- 위: 만든 카드 수(오늘 만든 수), 조회 합계, [플레이 하러 가기] 클릭 합계, 클릭률(클릭 ÷ 조회).
- 아래: 카드 목록 30개씩. 열은 닉네임(공유한 때 이름), 조회, 클릭, 만든 때, [열기](공유 페이지 새 탭). 정렬은 조회순(기본) / 클릭순 / 최신순.
- 조회·클릭은 같은 방문자 카드마다 하루 1번, 크롤러 제외(4.24). 방금 일어난 조회는 1분 안에 DB에 저장되지만 이 화면은 저장 전 값도 더해 보여 준다.
- 날짜별 추이와 가입 전환은 아직 없다(누적 열만 둔다).

### 13.9 통계
사이트가 얼마나 쓰이는지 그래프로 자세히 본다(한눈에 보는 요약은 대시보드, 13.11). 조회 전용이고 1분마다 다시 읽는다.

- 위: 지금 접속(방에 있는 사람, 봇 제외)과 오늘 값 카드 10개(활동 인원, 최고 동시 접속, 새 플레이어, 키워드 추가, 검색, 채팅, 댓글, ? 구슬, 충돌로 잃기, 자랑하기 카드). 카드마다 어제 값과 늘거나 준 양(▲▼)을 보여 준다.
- 시간별 접속 추이(24시간·3일·7일): 최고 동시 접속, 평균 동시 접속, 활동 인원(그 시간에 한 번이라도 방에 있던 사람).
- 시간별 활동량: 키워드 추가, 검색, 채팅, ? 구슬, 충돌로 잃기, 댓글, 새 플레이어.
- 하루별 추이(14·30·90일): 활동 인원(DAU), 최고 동시 접속, 새 플레이어, 그리고 추가·검색·채팅·댓글·자랑하기 카드 수.
- 사용자 구성: 전체 계정(운영자 계정 제외), Google 계정과 비율, 게스트, 최근 7일·30일 활동(WAU·MAU, `players.last_seen_at`), 플레이어 수, 관리자, 금지 중, 탈퇴.
- 운영: 처리 대기 신고 수, 키워드 상태별 수, 레벨 분포(1~10레벨은 하나씩, 11~20·21~30·31~50·51~100).
- 그래프: 마우스를 올리면 그 시간의 값, 범례를 누르면 선을 숨기고 보인다. 마지막 칸(이번 시간·오늘)은 집계 중이라 점선이다. 시간은 한국 시간으로 보여 준다.

모으는 방법
- 접속 인원: 10초마다 나라별 방의 접속자(봇 제외)를 세어 이번 시간의 최고·평균과 한 번이라도 있던 사람(활동 인원), 오늘의 최고·활동 인원을 메모리에 모은다. 1분마다 접속 중인 플레이어의 `players.last_seen_at`을 고친다.
- 활동 수: 추가(`+`), 검색, ? 구슬, 충돌로 잃기(빼앗김 포함), 채팅, 댓글, 자랑하기 카드 만들기, 새 플레이어(그 나라 닉네임을 처음 정함)를 일이 생길 때 메모리에서 센다(DB를 건드리지 않는다).
- 매시 정각(UTC)에 지난 한 시간의 값을 `site_hourly_stats`에 쓰고 메모리를 비운 뒤, 그날(나라 현지 날짜)의 `site_daily_stats`를 그날의 시간별 행에서 다시 만든다(덮어쓰므로 중복 합산이 없다). 그날 활동 인원은 시간별 합이 아니라 메모리의 그날 명단 크기다. 서버를 끌 때 이번 시간 값을 저장하고, 다시 켜면 같은 시간 행에 이어서 더한다.
- 서버가 갑자기 꺼지면 그 시간에 센 값이 사라지고, 다시 켜면 그날 활동 인원은 다시 센 값과 저장된 값 중 큰 값이라 조금 덜 셀 수 있다.
- 나라별 통계 설정은 없다. 서버가 여러 대가 되면 메모리 값을 Redis로 옮긴다.

### 13.10 사용자 관리
사용자(계정)를 찾아 기록을 보고 조치한다. 목록은 그 나라 플레이어(지금 KR) 기준이라 닉네임을 정하지 않은 계정은 보이지 않는다.

- 목록(30명씩): 닉네임 일부나 사용자·플레이어 번호로 찾고, 전체 / 🟢 접속 중 / Google / 게스트 / 관리자 / ⛔ 금지 중 / 탈퇴로 거르며, 표 위쪽 열 제목(레벨·유행도·누적 추가·최근 접속·가입)을 눌러 정렬한다. 처음 누르면 내림차순이고, 이미 고른 열을 다시 누르면 내림차순(↓) ↔ 오름차순(↑)이 바뀐다. 정렬되는 열은 ↕가 옅게 보인다. 검색 칸의 [찾기] 버튼 오른쪽에 사용자 수를 크게 보여 준다(걸러 보면 "조건에 맞는 N명", 아니면 "전체 N명"). 한 줄에 닉네임과 배지(접속 중, Google·게스트, 관리자, 금지, 그림 정지, 댓글 정지, 탈퇴), 레벨, 유행도(접속 중이면 방의 실시간 값), 보유 키워드, 누적 추가, 받은 신고 수(플레이어 신고 + 그 사람 댓글·채팅에 들어온 신고), 최근 접속, 가입일.
- 상세(줄을 누르면 오른쪽에): 원 모습(장착한 그림 또는 성장 캐릭터), 누적 수치(EXP·레벨, 유행도, 보유, 추가·검색, 댓글 점수, 빼앗기·봇 사냥·구슬·잃기, 활동한 날, 칭호 수와 장착 칭호, 댓글·채팅 수), 시각(가입, 최근 접속, 마지막 로그인, 마지막으로 키워드를 얻은 때, 닉네임 바꾼 때, 탈퇴), 제재 이력, 받은 신고 20개(원문 포함), 보관함, 최근 댓글 10개(지운 것 포함), 최근 채팅 10개.
- 조치(모두 한 번 더 묻는다)
  - 제재 걸기: 종류(계정 금지 / 그림 저장 정지 / 댓글 작성 정지 / 채팅 정지), 기간(1·3·7·30일·영구), 사유(필수, 500자). 계정 금지는 갱신 토큰을 모두 폐기하고 권한 캐시를 비워 바로 막으며, 접속 중이면 "운영 정책 위반으로 이용이 정지된 계정이에요"를 보내고 내보낸다. 관리자 계정은 권한을 먼저 빼야 금지할 수 있다. 같은 종류를 여러 번 걸면 가장 늦게 끝나는 것까지 유지된다.
  - 제재 풀기: 이력에서 [풀기]. `released_at`을 남기고 `users`의 제재 칸을 남은 제재로 다시 정한다.
  - 닉네임 바꾸기: 닉네임 규칙(4.1)을 그대로 검사하고, 사용자의 변경 간격에는 넣지 않는다. 접속 중인 방의 이름표도 바로 바뀐다.
  - 꾸미기 초기화: 그 플레이어의 꾸미기 프로필 1~3번 칸을 모두 지워 기본 모습(1번 칸 장착, 성장 캐릭터, 정해진 바탕색, 효과 없음)으로 되돌린다. 부적절한 그림 대응(4.9)이다.
  - 관리자 권한 주기·빼기: Google 계정만, 내 권한은 뺄 수 없다. 30초 캐시를 비워 바로 반영된다.
  - 강제 퇴장: 접속 중일 때만. "관리자가 접속을 끊었어요"를 보내고 내보낸다(다시 들어올 수는 있다).
- 내보내진 사람의 화면에는 "접속이 끊겼어요" 창과 [처음 화면으로]가 뜨고 다시 연결하지 않는다(연결 닫힘 코드 4001).
- 조치 기록은 제재만 `sanctions`에 남는다. 닉네임 바꾸기·꾸미기 초기화·권한 변경은 서버 로그에만 남는다.

### 13.12 AI 설명
키워드 카드의 AI 한 줄 설명(4.12, 10.4)을 관리하는 [AI 설명] 탭이다.
- 위에서 [갱신 요청] / [설명 없음] / [설명 있음]을 고른다. 갱신 요청은 요청이 많은 순이고, 키워드·상태·AI 설명(누가 언제 썼는지)·접수된 요청 수와 마지막 요청 시각·관리 단추를 한 줄에 보여 준다. 30개씩.
- [AI 재요청]: 제미나이에게 다시 받아 저장하고 그 키워드의 열린 요청을 모두 닫는다. 키가 없으면 단추가 꺼지고, 한도(429)·실패·모른다는 답이면 이유를 알려 주고 아무것도 바꾸지 않는다.
- [직접 수정]: 그 자리에서 1~200자로 쓰고 [저장]한다. 쓴 쪽이 "관리자가 씀"으로 남고 열린 요청을 모두 닫는다. 설명이 없는 키워드에도 직접 쓸 수 있다.
- [요청 닫기]: 설명은 그대로 두고 요청만 처리한 것으로 한다.
- 자동 생성을 포기한 키워드(모른다고 했거나 3번 실패)는 "설명 없음"에 "자동 생성을 포기"로 보이고, [AI 재요청]이나 직접 쓰기로 채운다.
- 대시보드(13.11)의 "처리할 일"에 "AI 설명 갱신 요청"(10건 이상 🔴, 1건 이상 🟡)이 있고 누르면 이 탭으로 간다.

### 13.13 아레나 관전
관리자가 지금 방을 원 없이 지켜보는 [관전] 탭이다(9.2). 플레이어로 들어가지 않으므로 랭킹·접속 인원·충돌·구슬·봇 수에 아무 영향이 없다.
- 화면: 실제 아레나와 같은 모습(원·이름표·칭호·테두리 효과·이동 효과·불꽃·구슬·세이프존·말풍선·이모트·미니맵)이 나오고, 내 원·조작은 없다. 지금은 KR 방이다.
- 보기: 마우스 휠·[−][+]·두 손가락으로 확대·축소(전체가 한눈에 들어오는 배율의 70%부터 300%까지, [전체]는 아레나 전체, [100%]는 실제 크기), 끌어서 이동, 미니맵을 누르면 그 자리로 이동, 키보드 `+` `-` `0`(전체) `Esc`(따라가기 해제). 멀리서는 원이 화면에서 3px 아래로 작아지지 않고, 이름은 화면에서 반지름 7px 이상인 원(또는 따라가는 원)만 보인다.
- 원을 누르거나 오른쪽 목록에서 고르면 그 원을 따라간다(흰 테두리로 표시, 멀리서 골랐으면 알아볼 만큼 확대). 목록은 점수 높은 순이고 닉네임으로 찾거나 봇을 뺄 수 있다. 위에 사람·봇·관전자 수, 따라가는 원의 레벨·점수·크기·콤보, 아래에 방 채팅(읽기 전용, 최근 100줄)이 보인다.
- 관전자는 방마다 10명까지, 관리자(`users.role = ADMIN`)만 들어올 수 있다. 탭을 닫거나 다른 탭으로 가면 접속이 끊긴다.

## 16. 열린 쟁점과 확인 필요

### 16.1 결정 필요
- 운영 DB의 스키마 반영 방식: 개발·테스트는 JPA 자동 반영(11.3)이다. 출시 전에 17절 SQL(`4-schema.sql`)을 기준으로 Flyway 마이그레이션으로 전환하는 시점과 방법을 정한다.
- 해외 지역(GLOBAL·JP·IN)의 외부 소스.
