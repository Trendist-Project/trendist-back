# Trendist 문서

> 유행을 아는 자, 커진다. 검색 트래픽으로 증명하는 "나의 유행 감각".

Trendist(트렌디스트)의 기획·설계 문서다. 이 백엔드 저장소의 `docs/`에서만 관리한다(프론트엔드 저장소에는 두지 않는다).

| 파일 | 내용 | 절 |
|---|---|---|
| [1-planning.md](1-planning.md) | 1부 기획: 개요, 플레이 흐름, 화면, 게임 규칙, 범위 | 1~6 |
| [2-tech.md](2-tech.md) | 2부 기술: 기술 스택, 프론트엔드, 백엔드, 트렌드 수집, 데이터 모델, 빌드·배포 | 7~12 |
| [3-operations.md](3-operations.md) | 3부 운영: 관리자 기능, 안전, 리스크, 열린 쟁점 | 13~16 |
| [4-schema.sql](4-schema.sql) | 4부 SQL: 스키마 DDL(MySQL 8) | 17 |

- 절 번호(1~17)는 네 파일에 걸쳐 이어진다. 코드 주석의 `(4.8)` 같은 번호가 이 절 번호다.
- 아직 정하지 못한 것은 16.1에, 직접 확인하지 못한 사실은 16.2에 모은다.

## 관리 원칙

- 기능을 바꾸면 같은 작업에서 문서도 고친다. 문서는 "앞으로 만들 기획"과 "지금 프로젝트의 의도·동작"이 어긋나지 않게 유지한다.
- 고칠 때는 해당 절을 직접 고치고, 아래 변경 이력에 판 번호와 바뀐 내용을 한 줄씩 남긴다.
- 문서만 바뀌는 커밋은 `docs:`, 기능과 함께 바뀌면 그 기능 커밋에 같이 넣는다.
