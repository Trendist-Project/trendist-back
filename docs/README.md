# Trendist 문서

> 유행을 아는 자, 커진다. 검색 트래픽으로 증명하는 "나의 유행 감각".

Trendist(트렌디스트)의 기획·설계 문서다. 이 백엔드 저장소의 `docs/`에서만 관리한다(프론트엔드 저장소에는 두지 않는다).

| 파일 | 내용 | 절 |
|---|---|---|
| [1-planning.md](1-planning.md) | 1부 기획: 개요, 플레이 흐름, 화면, 게임 규칙, 범위 | 1~6 |
| [2-tech.md](2-tech.md) | 2부 기술: 기술 스택, 프론트엔드, 백엔드, 트렌드 수집, 데이터 모델, 빌드·배포 | 7~12 |
| [3-operations.md](3-operations.md) | 3부 운영: 관리자 기능, 안전, 리스크, 열린 쟁점 | 13~16 |
| [4-schema.sql](4-schema.sql) | 4부 SQL: 스키마 DDL(MySQL 8) | 17 |

- 절 번호(1~17)는 네 파일에 걸쳐 이어진다. 코드 주석의 `(4.8)` 같은 번호가 이 절 번호다.
- 아직 정하지 못한 것은 16.1에, 직접 확인하지 못한 사실은 16.2에 모은다.

## 관리 원칙

- 기능을 바꾸면 같은 작업에서 문서도 고친다. 문서는 "앞으로 만들 기획"과 "지금 프로젝트의 의도·동작"이 어긋나지 않게 유지한다.
- 고칠 때는 해당 절을 직접 고치고, 아래 변경 이력에 판 번호와 바뀐 내용을 한 줄씩 남긴다.
- 문서만 바뀌는 커밋은 `docs:`, 기능과 함께 바뀌면 그 기능 커밋에 같이 넣는다.

## 변경 이력

### 107판 (2026-10-29)
- 점수 실시간 반영과 밸런스 설정 범위 검사에 남아 있던 환산 계수(×0.5)를 지움(9.2, 13.3)
- 외부 소스 `google`(구글 트렌드 실시간 인기)을 개요, 나라 표, `data_sources` 초기 데이터에 반영(1, 4.18, 11.3)
- 요구사항 점검에서 저장소에 없는 `00_요구사항.md` 참조를 지움(6)
- 랭킹을 지금 나라 방에 접속한 사람만 집계하는 리더보드로 바꿈. 방 메모리 점수로 정하고 DB 후보 조회를 없앰. 오른쪽 패널의 [랭킹] 탭 대신 아레나 오른쪽 위 모서리에 겹쳐 보여 주고, 미니맵처럼 [리더보드] 버튼과 L 키로 켜고 끔(3.2, 4.10, 4.14, 9.7)

### 106판 (2026-10-28)
- 문서를 한 파일(`trendist.md`)에서 기획·기술·운영·SQL 네 파일로 나누고, 백엔드 저장소에서만 관리하기로 함(이 파일, 12절)
- 키워드 최소 길이 제한 제거: 1~20자, 정규화 뒤에는 비어 있지 않고 100자 이하(4.6, 10.2)
- 이동 조작을 더블클릭에서 클릭(모바일 탭)으로 바꾸고, 이동 중에 다시 찍으면 목표를 바로 바꾸게 함(4.2)
- 자동 이동(드리프트) 제거: 조작하지 않으면 그 자리에 멈춤(4.2, 5.1)
- 로컬 개발 접속 주소를 http://localhost:8080 하나로 통일: 프론트 개발 서버 8080, 백엔드 8081(12절)
- 빠른 연타 때 내 원·화면이 떨리던 문제 수정: 예측을 서버 물리와 맞추고, 실제로 어긋날 때만 부드럽게 보정(8절)
- 클릭 이동을 초당 10회까지 받게 함(방향키는 초당 5회 그대로). 서버 빈도 제한을 종류별로 나눔(4.2, 9.5)
- 게임 화면에 [공지사항] [가이드·FAQ] [?] 버튼 추가, 조작 설명을 접고 펼 수 있는 카드로 옮김(3.2)
- 가이드 초기 카테고리에서 "이 게임의 계산 방식"을 빼고, 가이드에는 세부 수치를 쓰지 않기로 함. 초기 글을 넣음(4.17, 11.3)
- 공지 목록 API와 가이드 조회 API 구현(9.6)
- 로컬 개발 DB를 H2 메모리에서 우분투 MariaDB(DB `trendist`)로 바꿈. 자동 테스트는 H2 그대로(7절, 12절)
- 검색 결과 카드를 간단하게: 활성 조건 안내 문구와 누적 `+`·검색 수를 빼고 상태·트렌드 값·가진 사람 수·남은 시간만 보여 줌. 이미 가진 키워드 버튼 표기를 "+함"에서 "보유중"으로 바꿈(4.4)
- 나간 뒤 1분 안에 다시 들어오면 마지막 위치와 남은 입장 보호 시간을 이어 가게 함. 새로고침으로 위치를 바꾸는 악용 방지(4.2)
- 접속·새로고침 때 게임 화면으로 바로 들어가지 않고 항상 메인 화면부터 시작하게 함. 재방문 게스트는 [시작]을 누르면 같은 계정으로 이어 감(3.1)
- 내 정보 창 추가: [👤 내 정보] 버튼이나 HUD의 내 닉네임으로 열고, 기록을 보고 닉네임을 바꿈. 닉네임 변경 API와 변경 간격 설정값 `nickname_change_minutes` 추가(3.2, 4.1, 9.6, 13.3)
- 메인 화면 배경 원이 저마다 다른 경로·속도로 더 크게 움직이게 함(3.1)
- 점수 환산 계수(×0.5)를 없애고 키워드 점수를 트렌드 값과 같게 함. 화면에는 트렌드 값 하나만 보여 줌(4.4, 4.8, 9.4, 13.3)
- 방문자 ID 쿠키 이름을 `tv_id`에서 `visitor_id`로 바꿈(9.3)
- "내 트렌드 키워드"를 "보관함"으로 이름을 바꿈(전체)
- 키보드 이동 중 입력이 없는데 한쪽으로 끊기듯 움직이던 문제 수정: 서버에 닿은 입력만 예측에 넣고, 다시 연결되면 입력을 맞추고, 누르고 있는 동안 1초마다 방향을 다시 보냄. 떼는 신호를 못 받는 경우(창 전환, 보조키, 입력창 포커스)는 모두 뗀 것으로 봄(4.2, 8)
- 방향키를 짧게 눌렀다 떼면 최대 0.2초 더 미끄러지던 문제 수정: 방향키 입력을 초당 5회 제한 대신 바뀔 때마다 바로 보냄. 서버 방향키 빈도 제한을 초당 25회로(4.2, 9.5)
- 방향키 두 개를 함께 누르거나 짧게 눌렀다 떼면 멈춘 뒤 원이 혼자 조금 더 움직이던 문제 수정: 서버가 조작을 틱 경계(50ms)로 반올림하지 않고 도착 시각부터 적용하고, 클라이언트도 조작 시각에 정확히 바꾸며, 양쪽 가속을 같은 정확한 식으로 계산함. 멈춘 상태 허용 오차 3px. 방향키 합침 간격 16ms, 서버 방향키 제한 초당 60회(4.2, 8, 9.2, 9.5)
- 키보드에서 손을 떼 멈춘 뒤 원이 보정되듯 한 번 움직이던 문제 수정: 멈춰 있을 때 생긴 작은 보정(12px 이하)은 화면에 보이지 않게 두었다가 다음 움직임에 섞음(8)
- ? 구슬 추가: 아레나에 떠다니는 구슬을 먹으면 33% 확률로 🔥 키워드 하나가 무작위로 보관함에 들어가고 나머지는 꽝. 먹는 연출과 3초 결과 카드. 설정값 `orb_max`, `orb_spawn_seconds`, `orb_active_percent`(3.3, 4.20, 13.3)
- 구글 트렌드 실시간 인기 RSS를 외부 소스 `google`로 추가: 5분마다 제목을 🔥 키워드로 넣고 7일 유지(목록에 보일 때마다 지금부터 다시 7일, 설정값 `external_hold_hours`), 끝나면 목록에 있으면 연장·없으면 internal로 내리고 3명 미만이면 💤. `keywords.external_until` 추가(10.1~10.3, 17)
- 보관함 정렬 추가: 기본 최신순(넣은 시각), 정렬 칩(최신순·키워드·상태·트렌드 점수·남은 시간)을 누르면 정렬, 다시 누르면 방향 전환(4.5)
- 트렌드 값 표기를 "트렌드 21"에서 "21점"으로 바꿈(검색 카드, 보관함, 구슬 결과 카드)(4.4)
- 원 안을 여러 번 누르다 바깥을 누르면 원이 갔다가 되돌아오던 문제 수정: 서버 이동 명령 빈도 제한을 고정 1초 창에서 토큰 버킷(클릭 초당 12개, 최대 24개 모임)으로 바꿔, 메시지가 몰려 도착해도 버리지 않게 함(9.5)
